## 1. 三阶段模型（比「行数」更重要）

```
阶段 A  纯函数外提（低风险）     ← 我们主要已完成
阶段 B  决策/命令构建外提（中风险） ← 刚进入，仍小步
阶段 C  async effects / 薄壳（高风险）← 未做，需单独里程碑
```

| 阶段 | 内容 | 风险 | 当前 |
|---|---|---|---|
| **A** | 文本/判定/格式化/summary 纯函数 | 低 | **基本做完** |
| **B** | gate decision、messages 组装、prompt assembly | 中 | **进行中（小步）** |
| **C** | `orchestrator_node` / `_handle_tool_call` async 路由与副作用 | 高 | **刻意未做** |

---

## 2. 什么叫「OK 可以停」

### 2.1 推荐停点（产品+工程平衡）— **OK 线**

同时满足即可宣布 **「Orch P2 纯函数/中层阶段 OK」**：

1. **纯函数层清空**：壳内几乎只剩 async 路由 + 大块 prompt assembly / tool handle  
2. **入口稳定**：`graph` → `orchestrator_node` 签名不变；再导出不破  
3. **回归门禁**：orch 相关自动化绿；关键路径有钉死单测  
4. **依赖扫描**：包内模块无漏 import（AST 扫描 0 缺失）  
5. **心理数字（辅助）**：壳大约 **≤4500 行** 且 **阶段 A 完成**  

> 当前（第八刀后）：壳 **~4066 行**，阶段 A 完成，阶段 B 已开。  
> **已超过「纯函数阶段 OK 线」**，可以随时停；若继续只啃 B 的小块。

### 2.2 更进取的「薄壳 OK」— **不急**

要宣称 **薄壳完成** 才需要：

| 项 | 目标 |
|---|---|
| 壳行数 | **&lt; 800–1000**（设计稿曾写 400，可作终极目标） |
| `orchestrator_node` | 只做：读状态 → 调路由/effects → 返回 Command |
| `_handle_tool_call` | 拆到 `effects` / skill dispatch 模块 |
| 测试 | 行为对照黄金用例 + 关键 E2E 一条 |

这是 **独立里程碑**，成本与风险明显高于 1–8 刀之和，**不要和产品功能波并行硬冲**。

### 2.3 什么时候必须停

任一出现即停拆：

- 连续刀出现 **漏依赖 NameError** 且覆盖路径是主 Chat 高频路径  
- 回归变红且根因是拆分而非既有债  
- 与产品交付抢同一窗口

## 5. 建议的协作预期

1. **默认**：阶段 A 已 OK；阶段 B **按需小步**（每刀 200–500 行、钉死、扫依赖）。  
2. **可停**：任何时候停在当前点，转 annotation / 产品波，**不算半途而废**。  
3. **薄壳（阶段 C）**：单独立项，单独验收，**不**用「再拆几刀」口头带过。  
4. **成功标准**：可维护、可测、不炸主路径；**不是**把文件拆到最短。
