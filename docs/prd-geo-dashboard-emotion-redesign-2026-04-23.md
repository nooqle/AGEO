# PRD：GEO Dashboard 首页改版

> 日期：2026-04-23
> 角色：PM / UX / 架构联动方案
> 状态：更新稿
> 范围：Dashboard 首页、A5 首页投影视图、原型定义
> 非目标：不改 Chat 主流程、不重写 Canvas 报告机制、不新增行业级外部样本库

## 0. 相关上下文

当前仓库里已经存在 3 类能力，但它们的首页组织方式还不一致：

1. Dashboard 基础能力：品牌管理、品牌切换、进入分析、设置监测、品牌档案展开、打开最新报告
2. 首页摘要能力：`/v2/dashboard-home` 当前更像“最近一轮报告摘要”
3. A5 扩展能力：canonical 内部已经有提及、情绪、风险、平台、信源等分析骨架

因此本次不是从零做新首页，而是在不牺牲当前 Dashboard 功能的前提下，把首页从“报告入口”重组为“监测首页 + 最近一轮分析”。

## 1. 背景与问题

用户看到竞品 Dashboard 后，最直接的感受不是“它更漂亮”，而是“它更快让我知道品牌现在是稳、涨还是危险”。

当前 Specta 首页的核心问题有两类：

1. 首页叙事偏向“最近一轮报告入口”，不是“当前监测品牌的判断页”
2. 首页如果只追求改版视觉，容易把现有功能路径打断

当前具体问题：

1. 用户有多个监测品牌时，首页首先应该支持品牌切换，但改版过程中最容易误把“样本内品牌排行”当成“监测品牌切换”
2. 情绪、风险、优势这些判断没有形成清晰的一层结构
3. 词云能力需要，但当前 repo 里的 `keyword_analysis` 是通用 TF-IDF，不能直接当成情绪词云
4. 排行榜有价值，但不能继续带“提及份额”这类对首页判断帮助有限的字段
5. 头部和模块里如果加入自说自话文案，会破坏现有产品语境

## 2. 产品结论

本次首页改版的结论如下：

1. 首页必须从 `report-first` 转向 `dashboard-first`
2. 改版不能牺牲现有 Dashboard 的基础能力：`新建品牌`、`管理全部`、`进入分析`、`设置监测`、`展开品牌信息`、`打开最新报告`
3. 品牌切换只能发生在“品牌”区块的监测品牌卡上，不能发生在报告里的提及率排行榜上
4. 头部和主体模块不新增英文文案，不新增解释性文案，只保留产品标签、数据和操作
5. 不做“首位提及率”
6. 保留“提及率排名”，并扩成前十
7. 正负词云提升为首页一级模块，但必须由稳定情绪主题聚合驱动，不能复用通用 TF-IDF 冒充
8. 情绪趋势仍然必须等稳定快照字段，不允许前端硬拼

## 3. 产品目标

### 3.1 目标

将 Dashboard 首页改造成一个既保留现有管理能力、又能快速判断品牌状态的监测首页。

上线后的首页必须支持用户在 10 秒内完成以下动作或判断：

1. 在多个监测品牌之间切换当前查看对象
2. 判断当前查看品牌最近一轮分析的整体状态
3. 看出当前主要风险、优势、平台差异
4. 决定是否进入完整报告或监测设置

### 3.2 非目标

本轮明确不做：

1. 不做行业级 Top10 榜单
2. 不做首位提及率
3. 不重写 Chat、Canvas、Monitoring 全流程
4. 不用通用 TF-IDF 词云直接冒充情绪词云
5. 不为了追求像竞品而引入不可靠的趋势图

## 4. 用户与使用场景

### 4.1 主要用户

1. 品牌市场负责人：要快速判断当前查看品牌在 AI 回答中的状态
2. 内容 / SEO / AEO 运营：要知道该补哪些问题、哪些平台、哪些内容
3. 管理层 / 客户：要快速切换品牌并查看每个品牌最近一轮结果

### 4.2 首页使用场景

用户打开首页时通常要做的是：

1. 从多个监测品牌里切换当前查看对象
2. 进入某个品牌的分析或监测设置
3. 看该品牌最近一轮分析的核心结果
4. 决定要不要打开完整报告

## 5. 竞品对比与产品判断

### 5.1 竞品页面的优点

竞品最值得借的是信息架构，不是整页视觉：

1. 第一屏直接给核心判断指标
2. 情绪被提升成一级模块
3. 用户能迅速看到正向 / 负向语义分布
4. 趋势、平台、信源都在服务“为什么会这样”

### 5.2 我们当前的优点

我们当前更强的地方在于：

1. 已有成熟的品牌管理与监测入口
2. 首页品牌切换路径已经存在，不需要发明新入口
3. 提及项可回溯到问题、平台、答案、引用来源
4. 信源结构与官网 / 第三方来源区分更清晰
5. A5 canonical 已经具备较强的诊断骨架

### 5.3 当前真正的差距

真正的差距不是“完全没有能力”，而是：

1. 首页没有把情绪、风险、优势组织成稳定判断层
2. 首页 contract 还没有把词云、排行榜、平台诊断整理成前台可消费结构
3. 原有 Dashboard 的管理路径需要被保留，而不是被新版视觉吞掉

## 6. 首页设计原则

本次首页必须遵循以下原则：

1. 保留现有 Dashboard 操作路径
2. 先选监测品牌，再看该品牌最近一轮分析
3. 首页展示的是“监测首页 + 最近一轮分析”，不是纯报告入口
4. 仅保留产品标签、数据、操作，不新增自说自话文案
5. 所有首页判断都必须能回溯到问题、平台、回答或引用
6. 词云和趋势只建立在稳定字段上

首页从上到下建议固定为 5 个区块：

1. 顶部导航区
2. 概览区
3. 品牌管理区
4. 品牌档案与竞品分类区
5. 最近一轮分析区

### 7.1 顶部导航区

显示：

1. 产品标识：`Specta AI / 品牌AI助手`
2. `新建品牌`
3. 主题入口
4. 通知入口
5. 设置入口

要求：

1. 不新增英文副标题
2. 不新增解释型文案
3. 保持现有头部操作不丢失

### 7.2 概览区

显示：

1. 当前已管理品牌数
2. 累计分析次数
3. 当前查看品牌
4. 轻量状态标签

要求：

1. 只展示标签与数据
2. 不展示说明性正文

### 7.3 品牌管理区

显示：

1. 区块标题：`品牌`
2. 操作：`管理全部`
3. 监测品牌卡列表
4. `新建品牌` 卡

每张品牌卡必须包含：

1. 品牌头像 / 首字
2. 品牌名
3. 空间属性：个人空间 / 组织空间
4. 域名
5. 行业
6. 最近分析时间
7. 当前查看状态
8. 操作：`进入分析`
9. 操作：`设置监测`

要求：

1. 首页品牌切换只能发生在这里
2. 点击品牌卡后，下方所有分析模块联动切换

### 7.4 品牌档案与竞品分类区

保留现有入口与结构：

1. 区块标题：`品牌档案与竞品分类`
2. 操作：`展开品牌信息`
3. 品牌档案摘要
4. 竞品分类摘要

### 7.5 最近一轮分析区

区块内从上到下固定为：

1. 报告标题与最近更新时间
2. 操作：`打开最新报告`
3. 核心 KPI 行
4. 正负词云
5. 平台诊断
6. 高风险问题
7. 当前优势场景
8. 提及率排行榜
9. 信源结构

## 8. 首页模块详细定义

### 8.1 顶部导航与平台操作

必须保留现有首页头部能力：

1. 返回首页品牌入口
2. `新建品牌`
3. 主题
4. 通知
5. 设置

### 8.2 概览区

回答的问题：

1. 当前一共管理多少个品牌
2. 一共完成过多少次分析
3. 当前看的是哪个品牌

展示格式：

1. `概览`
2. 一行核心数字
3. 轻量状态标签

### 8.3 品牌管理区

回答的问题：

1. 我现在监测哪些品牌
2. 我当前看的是哪个品牌
3. 我要进入哪个品牌的分析或监测设置

展示格式：

1. 品牌卡网格
2. `管理全部`
3. `新建品牌`

### 8.4 品牌档案与竞品分类区

回答的问题：

1. 当前品牌档案有没有收录
2. 是否可以展开查看品牌与竞品信息

展示格式：

1. 区块标题
2. 展开 / 收起按钮
3. 摘要标签

### 8.5 KPI：提及率

回答的问题：

1. 品牌在当前问题样本中进入回答的比例是多少

展示格式：

1. 百分比
2. 辅助文案：进入回答的问题数 / 总问题数

### 8.6 KPI：提及率排名

回答的问题：

1. 在当前样本中，被 AI 回答提及的品牌里，我排第几

展示格式：

1. `#2`
2. 辅助文案：按当前样本中的提及率排序

说明：

1. 本期不做行业榜单
2. 本期只做“当前样本集内的品牌提及率排名”

### 8.7 KPI：正向占比

回答的问题：

1. 品牌被提及时，整体有多大比例是偏正向判断

展示格式：

1. 百分比
2. 辅助文案：以品牌被提及回答为分母

### 8.8 KPI：负向占比

回答的问题：

1. 品牌被提及时，有多大比例带有明显风险顾虑

展示格式：

1. 百分比
2. 辅助文案：以品牌被提及回答为分母

### 8.9 正负词云

目标：

让用户一眼看到当前品牌被提及时最突出的正向语义与负向语义。

展示格式：

1. `正向词云`
2. `负向词云`
3. 两列并排
4. 词大小按稳定口径排序

要求：

1. 不允许复用通用 TF-IDF 词云冒充情绪词云
2. 词云是一级模块，不是埋在明细里的附属图

### 8.10 平台诊断

目标：

让用户快速知道“哪些平台更容易放大风险，哪些平台更容易给出友好表达”。

每个平台展示：

1. 提及次数
2. 正向 / 中性 / 负向占比
3. 当前主要主题

### 8.11 高风险问题

每张卡片必须包含：

1. 问题标题
2. 风险等级
3. 涉及平台
4. 负向主题

### 8.12 当前优势场景

每张卡片必须包含：

1. 场景标题
2. 进入平台数量或状态标签
3. 是否已有官方引用
4. 当前正向理由

### 8.13 提及率排行榜

首页展示前十，但口径仍然是“当前样本中的品牌排行表”，不是行业榜。

字段：

1. 排名
2. 品牌名
3. 提及率
4. 被提及次数
5. 正向占比
6. 负向占比

要求：

1. 展示前十
2. 不展示提及份额

### 8.14 信源结构区

保留两层信息：

1. 来源类型分布：官网 / 垂媒 / 社区 / 视频 / 其他
2. 域名层分布：Top domains + 平台差异

2. 每个趋势点都必须回到稳定快照

## 12. 排名口径定义

提及率排名采用以下定义：

1. 分母：当前样本中的成功回答数
2. 分子：品牌在成功回答中被提及的回答数
3. 排名宇宙：当前样本中所有被提及品牌
4. 并列处理：提及率一致时按提及次数，再按品牌名稳定排序

说明：

1. 该排名不是行业份额
2. 该排名不是搜索市场份额
3. 该排名只说明“在当前问题集里谁更常进入回答”
4. 首页默认展示前十

## 13. 趋势口径定义

### 13.1 第一阶段

首页不展示“正向占比 / 负向占比”趋势图。

理由：

1. 当前 Snapshot 独立列没有这两个字段
2. 当前 TrendEngine 不支持这两个指标
3. 直接从原始 JSON 临时取值会导致口径漂移

### 13.2 第二阶段

如果要做情绪趋势，必须新增：

1. Snapshot 持久化字段：`positive_rate`、`negative_rate`
2. TrendEngine 支持这两个 metric
3. 最少 3 个有效快照后才展示趋势方向

## 14. API 与前端改造方案

### 14.1 API 方案

优先方案：

1. 继续使用 `/v2/dashboard-home`
2. 以新增可选字段方式扩展，保持兼容

原因：

1. 当前首页消费方单一
2. 加法扩展不会破坏旧解析
3. 可降低切换成本

兜底方案：

1. 如果首页字段继续膨胀，再升级到 `/v3/dashboard-home`

### 14.2 前端方案

首页从“最近一轮分析摘要卡”调整为“保留现有 Dashboard 功能的监测首页”。

## 15. 原型说明

本方案配套原型文件：

`docs/prototype-geo-dashboard-emotion-redesign-2026-04-23-v4.html`

原型重点表达：

1. 保留现有头部与品牌管理功能
2. 首页品牌切换发生在品牌卡区块
3. 最近一轮分析区的模块顺序
4. 正负词云提升为一级模块
5. 提及率排行榜扩到前十
6. 页面不使用英文和解释型文案

原型不是视觉定稿，重点是验证信息结构与产品边界。

## 16. 风险与开放问题

### 16.1 风险

1. 当前情绪识别仍有关键词启发式误差
2. 主题云如果定义不严，容易变成“看起来像有洞察”
3. 排名若不写清“样本内排名”，容易被误解为行业排名
4. 情绪趋势若快照数量太少，会形成误导

### 16.2 开放问题

1. 顶部是否保留时间范围筛选入口，还是先只保留最近更新时间
2. 品牌档案区默认展开还是默认收起
3. 词云点击后是否直接跳到对应问题 / 平台 / 证据
4. 前十排行榜是否需要支持展开查看更多

## 17. 成功标准

上线后应满足：

1. 用户进入首页后，能在多个监测品牌之间快速切换
2. 用户不需要先打开完整报告，也能理解当前品牌最近一轮分析的核心状态
3. 用户能看出至少 1 个主要风险与 1 个优势场景
4. 用户能看到前十排行与正负词云，而不会混淆品牌切换入口

## 18. PM 结论

这次改版的本质不是做一个更花的 Dashboard，而是让首页承担真正的“监测首页”职责，同时保留现有产品已经建立好的管理与操作路径。

第一阶段应优先把现有 Dashboard 能力和 A5 首页投影视图组织成一个统一首页。
词云与前十排行进入首页，但必须建立在稳定字段上。
趋势放到第二阶段，避免把不稳定口径提前产品化。
