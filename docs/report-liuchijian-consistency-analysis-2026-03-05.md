# 丽齿健 × 纽崔莱 跨品牌跨通道一致性对比分析报告

> **日期**：2026-03-05
> **品牌**：丽齿健（口腔护理，安利旗下） / 纽崔莱（保健品，安利旗下）
> **参与角色**：产品经理（Marty Cagan）、架构师（Martin Fowler）
> **数据基础**：丽齿健 5 轮采集（v2-v4 API, v5/v7 Browser）+ 纽崔莱 3 轮采集（v1-v3 API）

---

## 一、实验概述

### 我们做了什么？

用同一组问题，在多个 AI 平台上反复提问，测量"AI 回答的核心观点有多稳定"。

| 数据集 | 品牌 | 行业 | 通道 | 平台 | 问题数 | 采集轮次 | 对比对数 |
|--------|------|------|------|------|--------|---------|---------|
| 纽崔莱 v1/v2/v3 | 纽崔莱 | 保健品 | API | 豆包/混元/Kimi | 13 | 3 | 103 |
| 丽齿健 v2/v3/v4 | 丽齿健 | 口腔护理 | API | 豆包/混元/Kimi | 11 | 3 | 99 |
| 丽齿健 v5/v7 | 丽齿健 | 口腔护理 | Browser | 豆包/混元/Kimi/DeepSeek | 11 | 2 | 41 |

总计 **243 个对比对**，覆盖 2 个行业、2 种采集通道、4 个 AI 平台。

### 一致性怎么衡量？

我们从五个层次衡量"两次回答有多像"：

| 层次 | 含义 | 衡量方式 |
|------|------|---------|
| **文本相似度** | 逐字符比较 | SequenceMatcher |
| **引用重叠率** | 引用来源 URL 重叠 | Jaccard |
| **品牌提及** | 提到了哪些品牌 | 品牌词库 Jaccard |
| **产品品类** | 提到了哪些产品类型 | 产品词库 Jaccard |
| **立场/结论** | 推荐/不推荐/视情况等 | 立场标签 Jaccard |

**关键点综合** = 品牌×0.3 + 产品×0.25 + 立场×0.3 + 引用×0.15

## 三、发现 1：~60% 语义漂移常数（跨品牌、跨通道确认）

### 现象

三组独立实验的全平台关键点一致性：

```
纽崔莱 API:     58.9%
丽齿健 API:     59.9%
丽齿健 Browser: 60.2%
──────────────────────
均值:            59.7%
标准差:           0.68pp
变异系数:         1.1%
```

两个不同行业、两种不同采集通道、不同时间窗口（跨数天），全部收敛在 **59-60%** 区间。

### 配对间方差也极其稳定

| 数据集 | 配对1 | 配对2 | 配对3 | 极差 |
|--------|-------|-------|-------|------|
| 纽崔莱 API | 59.2% | 58.5% | 58.9% | 0.7pp |
| 丽齿健 API | 60.5% | 58.8% | 60.2% | 1.7pp |

### 这意味着什么？

**AI 回答的不稳定性本身是一个稳定常数。** 每次 AI 回答，约 60% 的核心语义骨架（提到了哪些品牌、推荐了什么产品、持什么立场）会被保留，约 40% 会随机变化。这不是某个平台的特例，不是某个行业的特殊性，而是 LLM 生成机制的固有特征。

### 采样次数与置信度

| 采样次数 | 核心语义覆盖率 | 适用场景 |
|---------|--------------|---------|
| 1次 | 60.0% | 快速预览（不可用于报告） |
| 2次 | 84.0% | Browser 默认（平台间已提供冗余） |
| 3次 | 93.6% | 标准报告 |
| 5次 | 99.0% | 高置信报告 |

**最小可区分差异（MDD）**：3次聚合下，BWVS 差异 < 8pp 应视为统计等价，不展示为"变化"。

## 四、发现 2：平台稳定性排名在 API 与 Browser 间完全反转

### 关键点一致性对比

| 排名 | API 模式 | | Browser 模式 | |
|------|---------|---|-------------|---|
| 1 | **混元 73.1%** | 🥇 | **豆包 62.7%** | 🥇 |
| 2 | 豆包 53.8% | 🥈 | 混元 59.6% | 🥈 |
| 3 | Kimi 52.7% | 🥉 | DeepSeek 59.2% | 🥉 |
| 4 | — | | Kimi 59.1% | |
| 极差 | **20.3pp** | | **3.6pp** | |

### 混元的"跌落"

| 混元指标 | API | Browser | 变化 |
|---------|-----|---------|------|
| 引用重叠 | **88.4%** | 50.0% | **-38.4pp** |
| 关键点 | **73.1%** | 59.6% | **-13.5pp** |
| 品牌提及 | 66.3% | 55.0% | -11.3pp |

### 豆包的"逆袭"

| 豆包指标 | API | Browser | 变化 |
|---------|-----|---------|------|
| 引用重叠 | 18.5% | **45.0%** | **+26.5pp** |
| 关键点 | 53.8% | **62.7%** | **+8.9pp** |
| 品牌提及 | 48.6% | 65.8% | +17.2pp |

### 为什么？

**API 和 Browser 不是同一模型的两种访问方式，它们是两套不同的推理系统。**

```
错误的心智模型:
  API ──→ [同一个模型] ←── Browser
  (两条路径，同一个目的地)

正确的心智模型:
  API ──→ [模型A + 搜索策略A + 预处理A + temperature_A]
  Browser ──→ [模型B + 搜索策略B + 预处理B + temperature_B]
  (两个不同的系统，碰巧共享品牌名)
```

混元 API 的高一致性（73.1%/88.4%引用）很可能来自：API 端较低的 temperature、不同的搜索策略、或缓存机制。Browser 端的搜索增强引入了实时互联网内容，增加了随机性。

### Browser 是一个"均衡器"

Browser 模式下四个平台的关键点一致性高度收敛（59.1%-62.7%，极差仅 3.6pp），而 API 模式极差达 20.3pp。

**原因**：Browser 模式下所有平台都执行真实网页搜索。对于同一个口腔护理问题，搜索引擎返回的顶部结果高度重叠。这些共同的搜索结果构成了一个"锚定信息集"，约束了各平台的输出空间，使得各平台的核心语义趋同。

### 辛普森悖论警告

全平台均值 API 59.9% ≈ Browser 60.2%（差仅 0.3pp），但内部排名完全反转。**只看整体数字会错过通道间的本质差异。数据存储层必须始终保留通道标签，永远不要混合 API 和 Browser 数据。**

## 五、发现 3：问题类型决定一致性幅度，且通道间存在反转

### 丽齿健 11 个问题的一致性排名

| Q# | 问题 | API关键点 | Browser关键点 | 变化 |
|----|------|----------|-------------|------|
| Q5 | 舒适达和冷酸灵哪个更管用？ | 61.3% | **76.2%** | +14.9pp |
| Q9 | 益生菌牙膏真的有用吗？ | **49.5%** | **75.5%** | **+26.0pp** |
| Q8 | 佳洁士、高露洁和狮王怎么选？ | **74.9%** | 58.6% | -16.3pp |
| Q10 | 高端牙膏和普通牙膏有什么区别？ | **73.7%** | 63.2% | -10.5pp |
| Q11 | 安利丽齿健真的好用吗？ | 70.3% | 57.7% | -12.6pp |
| Q7 | 国产牙膏品牌有哪些？ | 56.7% | 67.8% | +11.1pp |
| Q3 | 想找刷毛软的牙刷 | 60.5% | 53.5% | -7.0pp |
| Q2 | 不含酒精的漱口水哪款好？ | 61.6% | 53.5% | -8.1pp |
| Q4 | 全家用的全效牙膏 | 50.7% | 49.7% | -1.0pp |
| Q6 | 口腔喷雾或漱口水推荐 | 49.7% | 51.8% | +2.1pp |
| Q1 | 牙龈出血用什么牙膏？ | 49.5% | 48.6% | -0.9pp |

### Q9 反转：最大的惊喜

益生菌/酵素牙膏问题在 API 下排最不稳定（49.5%），在 Browser 下排第二最稳定（75.5%），跨度 **+26pp**。

**根因**：
- **API 模式（无搜索）**：益生菌与口腔护理的关联在模型训练语料中比较边缘，不同采样时模型的"编造"方向不同 → 低一致性
- **Browser 模式（有搜索）**：搜索"益生菌 口腔健康"返回一组相对固定的文章（该话题中文内容不多），搜索结果提供了强锚定 → 高一致性

### 问题类型分层

| 问题类型 | API 一致性 | Browser 一致性 | 推荐通道 |
|---------|-----------|---------------|---------|
| 具体品牌对比（Q8/Q10/Q11） | **70-75%** | 58-63% | API 足够 |
| 争议/新兴概念（Q9） | 49.5% | **75.5%** | **必须 Browser** |
| 开放式推荐（Q1/Q4/Q6） | 49-51% | 49-52% | 都不稳定，需多次采样 |
| 行业总览（Q7） | 56.7% | **67.8%** | Browser 更好 |
| 品牌对比 + 功效锚定（Q5） | 61.3% | **76.2%** | Browser 更好 |

**关键洞察**：API 对"模型已知的确定性知识"更稳定（品牌对比），Browser 对"需要检索外部信息的问题"更稳定（争议话题、新兴概念）。这对 A3 问题生成和 A4 采集策略有直接影响。

### Browser v5 vs v7 品牌提及变化

| 品牌 | v5 | v7 | 变化 |
|------|-----|-----|------|
| 云南白药 | 12 | 14 | +2 |

v7 总体品牌提及数高于 v5，可能与 v7 零失败（v5 有 3 个失败）有关。

### 二元性结论

AI 对品牌的提及呈现明显的**二元分布**：
- **头部品牌**（高露洁/狮王/云南白药）：跨版本跨通道稳定出现，提及率 20-30%
- **非头部品牌**（丽齿健）：自发提及接近零，仅在直接被问时出现

没有中间态。品牌要么在 AI 的知识图谱中占据稳定位置，要么完全不存在。

| 排名 | 纽崔莱（保健品） | 丽齿健（口腔护理） |

排序完全一致，且各平台在两个行业的数值高度接近（差异 < 2.5pp）。这说明平台间的稳定性差异是**架构性的**（模型大小、temperature 设置、检索策略），而非内容驱动的。

### 混元引用稳定性跨行业一致

| 平台 | 纽崔莱引用重叠 | 丽齿健引用重叠 |
|------|--------------|--------------|
| 混元 | 83.2% | 88.4% |
| Kimi | 21.6% | 16.6% |
| 豆包 | 12.7% | 18.5% |

混元的引用来源在两个行业中都高度稳定（83-88%），远超其他平台。但如前所述，这一优势在 Browser 模式下消失（降至 50%）。

### 丽齿健数据的增量贡献

纽崔莱作为保健品头部品牌，本身有较高提及率，无法观察到"低提及品牌"的行为。丽齿健恰好提供了这个对照：

| 维度 | 纽崔莱（头部品牌） | 丽齿健（非头部品牌） |
|------|------------------|-------------------|
| 自发提及率 | 较高 | **接近零** |
| 问题一致性跨度 | 较小 | **25pp（49.5%-74.9%）** |
| 品牌提及二元性 | 不明显 | **非常明显** |

## 八、推演与结论

### 8.1 已确认的通用规律

基于 243 个对比对、2 个行业、2 种通道、4 个平台的数据：

| 规律 | 数据支撑 | 置信度 |
|------|---------|--------|
| AI 回答的关键点一致性约 60% | 三组数据 58.9%/59.9%/60.2%，标准差 0.68pp | **高** |
| 文本相似度约 23-26%（措辞每次不同） | 三组数据 23.1%/26.3%/23.1% | **高** |
| 引用重叠约 41-43% | 三组数据 42.8%/41.2%/42.0% | **高** |
| 单次快照不可靠，需 3+ 次采样 | 配对间方差 < 2pp，说明 3 次已收敛 | **高** |
| API 和 Browser 是不同系统 | 混元反转 -13.5pp，豆包反转 +8.9pp | **高** |

### 8.2 需要更多数据验证的假设

| 假设 | 当前证据 | 需要的验证 |
|------|---------|----------|
| 60% 常数是品类无关的 | 保健品+口腔护理一致 | 需 3C 数码、美妆、食品饮料等品类 |
| Browser "均衡效应"是稳定的 | 四平台极差 3.6pp（1组数据） | 需更多品牌的 Browser 数据 |
| 争议型问题在 Browser 下更稳定 | Q9 反转 +26pp（1个样本） | 需更多争议型问题测试 |
| 品牌提及二元性是通用的 | 丽齿健 0% 自发提及 | 需测试中等知名度品牌 |

### 8.3 产品策略推演

#### 客户分层

| 客户类型 | 他们的痛点 | 我们的价值 | 付费意愿 |
|---------|----------|----------|---------|
| **头部品牌**（高露洁、纽崔莱） | "AI 提到我时说了什么？" | 情感监测、立场变化追踪 | 中高（防御性） |
| **挑战者品牌**（冷酸灵、参半）⭐ | "我有时出现有时不出现" | 出现率趋势、触发词分析 | **最高**（增长性） |
| **长尾品牌**（丽齿健） | "AI 根本不提我" | 诊断报告 + 优化建议 | 低（需教育） |

**甜蜜点客户是"挑战者品牌"** — 有预算、有焦虑、有可优化空间。

#### 产品话术锚定

> "AI 搜索引擎对品牌信息的可复现度约为 60%。这意味着每次用户提问，AI 有 40% 的内容是随机变化的。我们通过多次采样 + 统计聚合，帮你看清这 60% 中属于你的品牌有多少。"

#### 问题诊断矩阵

```

  │                      │                      │
  │  "待激活区"          │  "荒野区"            │
低│  问题结构有利但品牌   │  AI随机回答且不提你   │
提│  未被收录             │  → 短期ROI低，暂缓    │
```

## 十、跨通道分析：产品经理与架构师解读

### 10.1 产品经理（Marty Cagan）核心观点

**1. 对先前"~48% 品牌重叠"的精确印证**

护肤品实验（2026-02-28）得出 API vs Browser ~48% 品牌重叠。丽齿健跨通道品牌 Jaccard 50.9%，关键点 48.8%，跨行业一致。但本次数据揭示了更深的分层：

| 维度 | 跨通道一致性 | 含义 |
|------|------------|------|
| 品牌提及 | 50.9% | 品牌是否被提到 — 约一半可信 |
| 产品提及 | 57.5% | 推荐了什么产品 — 接近六成可信 |
| 立场 | 59.7% | 正面/负面倾向 — 相对稳定 |
| 引用来源 | **7.9%** | AI 参考了什么 — **几乎完全不可信** |

**结论：API 能回答"AI 推荐了谁"（约 50%），但完全无法回答"AI 为什么推荐"（引用 7.9%）。引用分析必须基于 Browser 数据。**

**2. 引用来源图谱是高价值差异化功能**

引用零重叠意味着 Browser 采集的引用是独有的、高价值的数据。品牌方最想知道"AI 为什么推荐竞品而不是我"，引用来源是唯一能回答这个问题的数据维度。建议在专业版（¥2,499）中作为核心卖点。

**3. 定价模型优化**

- 基础版（¥999，API）：重新定义为"趋势快照"，明确标注不含引用分析
- 专业版（¥2,499，Browser）：强调"真实用户视角 + 引用来源图谱"
- 新增"校准报告"功能：利用跨通道偏差数据做 API→Browser 推算

**4. 混元修正**

混元跨通道降幅最小（-8.9pp），引用重叠 20.1%，字数几乎不变。混元并非"Browser 跌落"，而是 **API 和 Browser 本身就比较一致**。对混元来说，API 数据已相当可用。

### 10.2 架构师（Martin Fowler）核心观点

**1. 11pp 是"通道偏移量"，可建模但非常数**

跨通道 6 个配对的关键点落在 47.8%-49.4%（极差 1.6pp），说明这个偏移是系统性的。但范围随问题类型浮动：

- 具体品牌对比：偏移 ~6-8pp（RAG 管线影响小）
- 开放式推荐：偏移 ~15-18pp（RAG 管线影响大）

**2. "两个不同系统"论断的精炼**

```
维度           同通道    跨通道    差距    判定
──────────────────────────────────────────────
引用重叠       ~40%      7.9%     -32pp   极强分离
文本相似度     ~25%      13%      -12pp   强分离
品牌一致性     ~60%      50.9%    -9pp    中度分离
产品一致性     ~60%      57.5%    -3pp    弱分离
──────────────────────────────────────────────
```

**精炼论断：API 和 Browser 在信息源层是两个完全不同的系统（引用 -32pp），但在语义层共享一个底层认知基础（产品仅 -3pp）。** 像同一个教授在两个不同图书馆写的论文 — 参考文献完全不同，但核心观点有连贯性。

**3. BWVS 必须分通道计算**

```
BWVS_final = w_browser × BWVS_browser + w_api × BWVS_api

维度处理策略：
- 提及率(0.35): 分通道计算，取 Browser 优先
- 位置分(0.25): 分通道计算，取 Browser 优先
- 情感(0.15):   可跨通道聚合（立场差异最小）
- 覆盖率(0.15): 分通道计算，Browser 权重更高
- 引用质量(0.10): 严格通道隔离（重叠仅 1.4%）
```

**4. 数据模型设计：channel 是一等公民**

```
fetch_result
├── platform       -- doubao / kimi / hunyuan / deepseek
├── channel        -- "api" | "browser"    ← 一等字段，不可省略
├── run_index      -- 同通道内第几次采样
├── raw_text / citations / extracted_brands / sentiment
└── metadata

bwvs_score
├── brand_id / platform / channel
├── mention_rate / position_score / sentiment / coverage / citation_quality
├── composite_score / confidence / sample_count
└── channel_divergence   -- 跨通道偏离度（监控用）
```

**关键原则：现在就加 channel 字段，不要等。** 这是典型的"早期廉价、晚期昂贵"的架构决策。

**5. 混元是"校准锚点"**

混元跨通道一致性最高（57.4%），适合做品牌提取管线的交叉验证。如果混元的跨通道分离度突然变化，应触发告警。

## 十一、全局结论

### 三个常数

基于 243+ 对比对的全部数据，我们确认了三个跨品牌、跨行业的经验常数：

| 常数 | 值 | 含义 | 数据支撑 |
|------|-----|------|---------|
| **语义漂移常数** | ~60% | 同通道关键点一致性 | 纽崔莱API 58.9% / 丽齿健API 59.9% / 丽齿健Browser 60.5% |
| **通道偏移量** | ~11pp | 跨通道比同通道额外降低 | 6配对均值48.8%, 范围47.8-49.4% |
| **品牌重叠率** | ~50% | 跨通道品牌提及 Jaccard | 护肤品~48% / 丽齿健50.9% |

### 一句话总结

**AI 平台有两个"面孔"—— API 面和 Browser 面。它们分享约 50% 的品牌认知，但引用着完全不同的信息源（重叠仅 1.4%）。任何严肃的 AEO 监测都必须基于 Browser 面，因为那才是消费者看到的现实。**
