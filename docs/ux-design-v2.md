### 4.5 基线重跑机制

- 用户点击 [重新运行基线] 或在聊天中输入类似"重新分析"
- 系统提示："将重新执行基线分析，新结果将替换当前基线数据。确认继续？"
- 旧基线数据保留为历史版本（与 Issue #5 的版本管理联动）
- 重跑使用最新的品牌信息（如竞品可能已更新）

### 4.6 基线问题生成策略

基线问题由 A3 根据品牌+行业+竞品信息自动生成，不经过 A2 画像。问题类型：

| 类型 | 示例 | 数量 |
|------|------|------|
| 行业推荐 | "最好的晚霜品牌有哪些" | 2 |
| 品牌口碑 | "兰蔻的口碑怎么样" | 2 |
| 竞品对比 | "兰蔻 vs 雅诗兰黛哪个好" | 2 |
| 产品评价 | "兰蔻小黑瓶值得买吗" | 2 |

总计约 8 个全景问题，覆盖品牌在 AI 平台上最常见的查询模式。

## Issue #5: 交付物导航合并与历史回溯（v2）

### 5.1 导航分组策略

基于产品确认，交付物导航采用**两级分组**：

- **第一级**：基线 vs 场景
- **第二级**：按类型（报告/问题/抓取等）

### 5.2 ArtifactNav 重新设计

#### 分组逻辑

```typescript
// 分组逻辑伪代码
type ArtifactGroup = {
  category: 'baseline' | 'scenario';  // 基线 vs 场景
  label: string;                       // "基线" | 画像名称
  items: ContentGroup[];               // 按类型分组的内容
};

type ContentGroup = {
  type: CanvasContentType;
  items: CanvasContent[];              // 同类型的多个版本
  latestId: string;
};
```

**分组依据**：
- 如何判断一个交付物属于"基线"还是"场景"？
  - 方案 A：CanvasContent 增加 `category: 'baseline' | 'scenario'` 字段（需后端配合在 output_ready 事件中传递）
  - 方案 B：前端根据执行上下文推断（基线阶段产出的 = baseline，画像选择后产出的 = scenario）
  - **推荐方案 A**，更可靠

### 5.4 跳转对话上下文

**交互流程**：
1. 用户在版本切换器中点击 [跳转对话]
2. 获取该交付物的 `relatedMessageId`
3. ChatPanel 中执行 `scrollToMessage(messageId)`
4. 目标消息添加高亮效果

**高亮效果**：
```css
/* 目标消息临时高亮 */
.message-highlight {
  position: relative;
  animation: message-highlight 2s ease-out forwards;
}

.message-highlight::before {
  content: '';
  position: absolute;
  left: -8px;
  top: 0;
  bottom: 0;
  width: 3px;
  background: var(--brand-primary);
  border-radius: 2px;
  animation: highlight-bar 2s ease-out forwards;
}

@keyframes message-highlight {
  0% { background-color: var(--brand-bg, rgba(99,102,241,0.06)); }
  100% { background-color: transparent; }
}

@keyframes highlight-bar {
  0%, 70% { opacity: 1; }
  100% { opacity: 0; }
}
```

**实现要点**：
- ChatPanel 需要暴露 `scrollToMessage(id: string)` 方法
- 可以通过 Zustand store 或 ref 回调实现跨组件通信
- MessageList 中每条消息需要 `id` 属性的 DOM 节点
- `relatedMessageId` 需要后端在 `output_ready` 事件和 API 返回中提供

## 附录：与 Issue #6 的联动

Issue #4/#5 的新组件（品牌确认卡片、引导卡片、版本切换器等）必须从设计之初就同时考虑深色和浅色模式。所有新组件应：

1. 完全使用 CSS 变量，零硬编码颜色值
2. 使用 `light-theme-redesign.md` 中定义的新变量（如 `--brand-bg`, `--brand-text`）
3. 按钮遵循统一的状态设计（见 light-theme-redesign.md 第 3 节）
4. 间距遵循统一规范（见 light-theme-redesign.md 第 5 节）
