## 一、目标与边界

Phase 1+2 的画布是**固定拓扑、位置自由**：节点关系写死，用户只能拖动排布、开关平台。Phase 3 走向真正的生产线编排：

1. **连线改接**：用户可断开/重连数据流，定义自己的加工路径。
2. **节点增删**：从节点库拖入新节点，删除不需要的节点。
3. **新节点类型**：内容创作、数据分析，让生产线从"洞察"延伸到"行动"。

**边界（本期不做）**：多人协作、版本历史、节点市场、自定义代码节点。

## 二、关键架构决策：执行与编排的关系（需要先拍板）

自由编排最大的分歧点在**执行引擎是否跟随自定义拓扑**。两个方案：

### 方案 A：视图层编排（纯前端，轻）

- 拓扑编辑只影响画布展示与组织，**执行仍按内置固定流水线**（A1→A2→A3→A4→A5）。
- 编排数据（节点/连线/位置）持久化 localStorage，按实体记忆。
- 优点：零后端改动，2-3 天可交付；风险小。
- 缺点：编排是"假的"——用户改了拓扑，跑的还是老流程，预期落差大。

### 方案 B：全栈编排（真执行，重）

- 拓扑持久化到后端（新表 `flow_topology`：entity_id / nodes / edges / version）。
- 执行引擎改为按拓扑 DAG 调度：节点 = 执行单元，连线 = 数据依赖。
- 新节点类型（内容创作/数据分析）作为可插拔执行单元注册。
- 优点：真正的生产线编排，企业知识系统沉淀的底座。
- 缺点：后端执行引擎重构（当前 workflow 是写死的 LangGraph），工作量 2-3 周，高风险。

### 建议：A 先行，B 分步

**Phase 3a（本次）= 方案 A + 新节点类型的"定义与占位"**：
- 连线改接、节点增删、节点库面板——全部前端落地。
- 新节点类型先定义类型学、配置面板、产出物契约，**执行侧先接现有能力**（如数据分析节点调用 A5 报告，内容创作节点先占位标注"规划中"）。
- 明确定位：3a 交付的是"编排体验 + 拓扑数据模型"，为 3b 的真执行铺路。

**Phase 3b（后续）= 方案 B**：执行引擎拓扑化改造，单独立项评估。

这样用户每周都有可见进展，且不会在执行引擎重构上一次性押注过大。

## 三、Phase 3a 详细设计

### 3.1 连线改接

| 项 | 设计 |
|---|---|
| 交互 | 从输出端口拖出连线 → 落到目标节点的输入端口；悬停连线显示断开按钮（或选中后 Delete） |
| 校验 | `isValidConnection`：①禁止成环（DAG 校验，DFS 检测）②输入端口单连接（新连线替换旧连线）③类型匹配（产出物类型 → 输入类型，如"答案原文"只能进消费答案的节点） |
| 内置保护 | 资产节点（问题集/词库）的输出可改接，但核心骨架删除时二次确认（"断开后该节点不再接收数据"） |
| 持久化 | 自定义拓扑存 localStorage `amway-flow-topology:{entityId}`；「重置布局」同时恢复默认拓扑 |
| 执行语义 | 3a 中改接只影响视觉与数据流展示；运行仍走内置流水线，视图头上加一行轻提示"自定义拓扑仅影响展示，执行路径不变" |

### 3.2 节点增删

| 项 | 设计 |
|---|---|
| 节点库 | 画布左侧可折叠面板，分组列出可添加节点（见 3.3）；拖入画布即创建 |
| 删除 | 节点选中后 Delete 或右键菜单；内置骨架节点（采集/抽取/图谱/报告）不可删，只能改接；平台子节点不可删（用开关代替） |
| 上限 | 单画布自定义节点 ≤ 20 个（防止画布失控） |

### 3.3 新节点类型（3a 先落地 2 个）

| 类型 | 视觉 | 输入 | 输出 | 3a 执行语义 |
|---|---|---|---|---|
| **数据分析** | 胶囊形，紫色系 | 圈层图 / 报告原文 | 分析结论卡片 | 复用 A5 已有产物做二级解读（调现有 report API），3a 即可真跑 |
| **内容创作** | 胶囊形，橙色系 | 实体词库 / 分析结论 | 文案草稿 | 3a 先占位：配置面板可编辑prompt模板，执行标注"规划中"，点击产出徽章显示模板预览 |

### 3.4 状态与持久化模型

```ts
interface FlowTopology {
  version: 1;
  customNodes: Array<{ id: string; type: 'analysis' | 'content'; position: XYPosition; config: Record<string, unknown> }>;
  customEdges: Array<{ id: string; source: string; target: string; sourceHandle?: string; targetHandle?: string }>;
  removedEdgeIds: string[];   // 内置拓扑中被用户断开的连线
}
```

- 加载顺序：内置拓扑 → 应用 removedEdgeIds 删除 → 合并 customNodes/customEdges。
- 与布局存储（`amway-flow-layout`）分离：布局管位置，拓扑管连接，互不污染。

## 五、风险

1. **拓扑编辑的认知负担**：改接后执行路径不变可能让用户困惑 → 用视图头轻提示 + 连线改接时的即时反馈文案管理预期。
2. **localStorage 拓扑的迁移**：3b 上后端存储时需要迁移逻辑 → 拓扑模型带 version 字段，3a 末预留导出 JSON 能力。
3. **环校验遗漏导致图异常**：DAG 校验必须覆盖改接与拖入两条路径，附单元测试。

## 六、待确认问题（已全部确认 2026-07-19）
