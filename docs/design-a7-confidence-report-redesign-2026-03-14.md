# A7 置信度报告重设计（PM + UX + 架构联合稿）

> **作者**: Marty Cagan + Don Norman + Martin Fowler
> **日期**: 2026-03-14
> **状态**: 设计定稿（待实施）
> **范围**: A7 `confidence_signal` Artifact 的报告形式与内容重构
> **保留前提**:
> - 报告名称继续使用：`置信度报告`
> - 底层评分继续使用现有 AICE 评估逻辑
> - 执行继续由 A7 Agent 负责
> - 不改 A7 的基本任务定位，不新增一级页面

---

## 1. 问题定义

当前 A7 置信度报告虽然已经具备：

1. citation 来源提取
2. AICE 评分
3. 聚合摘要
4. 额外评估

但当前交付形态仍然停留在：

- 链接评分列表
- 品牌 / 竞品高分排名
- 零散维度说明

这导致报告有两个核心问题：

1. **价值感弱**
   - 用户看到的是“哪些链接分高”，但看不到“这和我的品牌占位战略有什么关系”
2. **方法论缺失**
   - 报告没有把引用频次、语料质量、阵营归属与内容动作连成一个完整决策系统

因此，本次重设计不是更换评分引擎，而是**重写 A7 置信度报告的解释框架、信息架构和行动输出**。

---

## 2. 新的底层逻辑

本次设计采用用户提出的完整逻辑作为 A7 报告的解释母体：

- **大模型 = 阿赖耶识**
- **网页语料 = 种子**
- **AI 回答 = 现行**

置信度报告的职责，不再只是告诉用户“哪条链接分高”，而是要回答：

1. 这些被 AI 引用的语料分别属于谁的阵地
2. 这些语料在 AI 语境中处于什么生态位置
3. 哪些语料正在稳固我方认知
4. 哪些语料虽然被引用，但本质脆弱
5. 哪些竞品低质语料之所以被引用，是因为市场缺少更好的替代供给
6. 我方应该如何通过“修我”来长期占位

这意味着：

**A7 置信度报告 = AI 语境下的语料生态诊断报告。**

---

## 3. 产品定位

### 3.1 报告定义

`置信度报告` 是 A4 引用来源在 AI 语境中的生态诊断与修我行动报告。

它不是：

- 普通链接评分表
- SEO 技术审计页
- 单纯的高分榜单

它是：

- 对 AI 回答背后引用语料的阵营分析
- 对语料质量与被引用强度的联合分析
- 对品牌长期 AI 占位能力的修缮指引

### 3.2 报告目标

本报告需要帮助用户完成 4 个判断：

1. **看清阵地**
   - 哪些引用源属于我方、竞方、共业语料
2. **看清生态位置**
   - 哪些语料是高频高质，哪些是高频低质
3. **看清风险与机会**
   - 哪些内容在被 AI 使用，但存在明显脆弱性
4. **看清修我方向**
   - 哪些应该固化，哪些应该修缮，哪些应该放弃，哪些应该补位

## 4. 核心数据模型与分类逻辑

## 4.1 阵营分类

对每个被抓取到的 citation URL，A7 在现有 AICE 评分之外，新增 `entity_classification` 判断，将来源划分为三个阵营：

### `Brand`

满足以下任一条件：

1. 链接域名属于我方官网或我方自有站点
2. 链接内容明确且主要正面介绍我方品牌 / 产品 / 技术 / 观点

### `Competitor`

满足以下任一条件：

1. 链接域名属于核心竞品官网或竞品控制站点
2. 链接内容明确且主要介绍竞品品牌 / 产品 / 技术 / 观点

### `General Knowledge`

满足以下条件之一：

1. 行业科普
2. 研究报告
3. 标准文档
4. 宏观第三方评测
5. 无明显品牌倾向的通用知识来源

### 4.1.1 判定原则

分类判断以“链接域名 + citation 标题 + 正文摘要 + 页面主体内容”综合给出，不再仅靠前端关键词猜测。

其中：

1. 域名归属是强信号
2. 页面正文主题归属是必要补充
3. 若无明确品牌指向，则归入 `General Knowledge`

---

## 4.2 二维坐标轴

对每一个完成阵营分类的 URL，计算两个核心维度：

### Y 轴：引用频次 `frequency`

定义：

- 该 URL 在同一轮话题抓取中，被多个模型回答引用的总次数

来源：

- 直接复用当前 A7 item 上已有的 `occurrences`

业务意义：

- 频次越高，说明它在当前 AI 语境中的“现行”强度越高

### X 轴：AICE 置信度 `aice_score`

定义：

- 继续复用现有 AICE 总分，范围 `0-100`

来源：

- 直接复用当前 `overall_score`

业务意义：

- 分数越高，说明该语料越客观、越结构化、越可核查、越不易被 AI 曲解

### 4.2.1 象限分割阈值

建议默认：

1. `AICE >= 75` 视为高置信区
2. `frequency >= median_frequency` 视为高频区

其中：

- `75` 是产品默认分割线，但必须作为可配置参数保留，便于未来按实验或业务判断调整
- 高频阈值不写死，优先取当前样本的中位数或稳定的样本阈值

原因：

- AICE 高低需要稳定业务分水岭
- 频次高低必须跟随具体报告样本规模变化

---

## 4.3 四象限定义

基于 `frequency + aice_score`，A7 将每条来源划入四象限。

| 象限 | 数据特征 | 业务定义 | 修我策略 |
| :--- | :--- | :--- | :--- |
| 第一象限 | 高频 + 高分 | 定海神针 | 提炼优秀基因，固化 SOP |
| 第二象限 | 高频 + 低分 | 虚假繁荣 | 重点修缮，净化语料或降维覆盖 |
| 第三象限 | 低频 + 低分 | 沉寂噪音 | 战略性放弃 |
| 第四象限 | 低频 + 高分 | 高潜伏藏 | 保持可用，等待提示词唤醒 |

### 4.3.1 解释原则

报告中每个象限都必须带有明确业务语言，不可只显示：

- Q1
- Q2
- Q3
- Q4

用户看到的必须是“定海神针 / 虚假繁荣 / 沉寂噪音 / 高潜伏藏”这类有决策意味的命名。

## 5. 新的报告信息架构

当前的“品牌高分榜 / 竞品高分榜”不是新版主结构。

新版置信度报告建议采用 6 个区块。

## 5.1 报告首屏：总论区

目标：

- 用一句话告诉用户，这份报告在判断什么

建议信息：

1. 报告标题：`置信度报告`
2. 报告副标题：
   - `评估 AI 回答引用语料的阵营分布、生态位置与修我方向`
3. 顶部总览指标：
   - 总 citation 数
   - 我方阵营数
   - 竞方阵营数
   - 共业阵营数
   - 平均 AICE 分
   - 第二象限占比
4. 一句诊断结论：
   - 例如：`当前 AI 对该话题的引用生态呈现“竞方高频占位、我方高质低频、行业通识补位”的结构。`

首屏回答的问题是：

**“这批被引用语料的整体生态是什么样？”**

---

## 5.2 语境生态坐标系

这是新版报告的核心视觉主图。

### 展示方式

一个二维散点矩阵：

- X 轴：AICE 置信度
- Y 轴：引用频次

每个点代表一个 citation URL。

### 视觉编码

1. 颜色代表阵营：
   - 蓝色：我方
   - 红色：竞方
   - 灰色：共业
2. 点大小可弱映射引用频次或保持固定
3. 象限背景标出四个业务命名
4. Hover / 点击后显示简卡：
   - 标题
   - 域名
   - 阵营
   - 频次
   - AICE 分
   - 象限定义

### 图下摘要

矩阵下方追加一句解释：

- `右上象限代表已被 AI 高频采纳且语料质量稳定的来源；左上象限代表当前虽被频繁引用，但底层质量脆弱的来源，是优先修我区域。`

---

## 5.3 象限总览区

在矩阵下方，用 4 张卡片总结四象限，不直接铺链接。

每张卡需要包含：

1. 象限名称
2. 来源数量
3. 代表阵营分布
4. 一句业务解释
5. 一条建议动作

例如第二象限卡片：

- 名称：`虚假繁荣`
- 数量：`9`
- 阵营分布：`我方 3 / 竞方 4 / 共业 2`
- 解释：`这些来源已被高频引用，但语料质量不稳，存在被更优来源替代的高风险。`
- 动作：`优先处理我方来源，其次针对竞方低质高频内容进行降维覆盖。`

---

## 5.4 四个深度分析区块

这是新版报告的核心分析正文。

仅重点展开四类来源：

1. 我方阵地：坚如磐石（善因固化）
2. 竞方阵地：坚如磐石（见贤思齐）
3. 我方阵地：被引用但置信度不高（发露修缮）
4. 竞方阵地：被引用但置信度不高（法施填补）

这四块分别对应：

- `Brand + Q1`
- `Competitor + Q1`
- `Brand + Q2`
- `Competitor + Q2`

### 5.4.1 每个区块的统一结构

每个区块都必须包含 3 层信息：

1. **阵地定义**
2. **高 / 低置信原因拆解**
3. **修我行动建议**

### 5.4.2 展示粒度

每个区块建议只展示：

1. 1 条区块总论
2. 3-5 条代表链接
3. 每条链接的原因与建议

不要把全部链接平铺成明细表，否则会稀释决策密度。

---

## 5.5 共业阵营观察区

虽然深度分析重点不放在 `General Knowledge`，但共业阵营必须存在。

它承担的角色不是品牌对抗，而是：

1. 揭示行业认知母体由哪些通用知识构成
2. 识别哪些共业来源正在充当 AI 的默认解释框架
3. 判断我方是否缺乏可进入共业语境的内容形态

建议展示：

1. 共业高频来源 TOP 5
2. 共业高分来源 TOP 5
3. 一条解释：
   - `当前 AI 对该主题的基础认知，主要由研究报告、百科词条与第三方测评构成；我方语料尚未进入共业语境层。`

---

## 5.6 修我行动清单

报告最后必须落到行动，而不是停在解释。

建议按优先级生成 `修我行动清单`：

### P0：立即修缮

来源：

- 我方第二象限内容

动作类型：

- 重写官网页面
- 重构标题层级
- 减少主观修饰
- 增加可核查数据
- 补充 Schema

### P1：对标固化

来源：

- 我方第一象限内容
- 竞方第一象限内容

动作类型：

- 提炼模板
- 形成 SOP
- 对标内容结构

### P2：降维覆盖

来源：

- 竞方第二象限内容

动作类型：

- 产出更高质量的替代性内容
- 用高置信我方语料争夺下一轮引用权

### P3：战略性忽略

来源：

- 第三象限噪音来源

动作类型：

- 不投入资源

## 6. 单条链接的卡片结构

无论出现在矩阵 hover、象限分析区还是追加评估区，单条来源卡片建议统一为下列结构：

1. 标题
2. URL / 域名
3. 阵营标签
4. 象限标签
5. 引用频次
6. AICE 总分
7. 2-3 个关键原因
8. 1 条修我建议

示例字段：

```json
{
  "title": "xx.com/2025-ai-architecture-whitepaper",
  "entity_classification": "brand",
  "quadrant": "q1_anchor",
  "frequency": 12,
  "aice_score": 92,
  "primary_reasons": [
    "C9b Schema 完整",
    "C3 可核查证据强"
  ],
  "repair_action": "提炼为后续技术白皮书模板"
}
```

## 7. 数据结构改造建议

本次不改 AICE 打分引擎，但需要扩展 A7 `confidence_signal` item。

## 7.1 顶层报告结构

建议在现有 `report_kind = confidence_signal` 之下，把数据结构扩展为：

```json
{
  "report_kind": "confidence_signal",
  "artifact_kind": "confidence_signal",
  "headline": "置信度报告",
  "subtitle": "评估 AI 回答引用语料的阵营分布、生态位置与修我方向",
  "summary": {},
  "ecosystem_matrix": {},
  "quadrant_overview": [],
  "analysis_blocks": [],
  "general_knowledge_insight": {},
  "repair_actions": [],
  "auto_items": [],
  "manual_items": []
}
```

## 7.2 item 扩展字段

当前 `ConfidenceSignalItem` 建议新增：

```json
{
  "entity_classification": "brand | competitor | general_knowledge",
  "frequency": 12,
  "aice_score": 92,
  "quadrant": "q1_anchor | q2_false_prosperity | q3_noise | q4_sleeping_asset",
  "quadrant_label": "定海神针",
  "primary_reasons": [],
  "repair_action": "",
  "analysis_group": "brand_q1 | competitor_q1 | brand_q2 | competitor_q2 | general"
}
```

### 字段映射关系

现有字段可直接复用：

1. `occurrences -> frequency`
2. `overall_score -> aice_score`
3. `dimension_scores -> primary_reasons` 的原始依据
4. `recommendations -> repair_action` 的原始依据

## 8. A7 后端职责调整

本次不更换 A7 Agent，只扩展其输出职责。

当前 A7 已负责：

1. citation 提取
2. URL / 文本评分
3. aggregate findings
4. manual extra evaluate

新版 A7 需要新增：

1. `entity_classification`
2. `quadrant assignment`
3. `analysis block grouping`
4. `repair action synthesis`
5. `matrix summary synthesis`

### 8.1 推荐执行顺序

```text
extract citations
  ->
run AICE score
  ->
classify entity camp
  ->
compute frequency + score quadrant
  ->
group by analysis block
  ->
synthesize repair actions
  ->
build confidence report payload
```

### 8.2 与现有 extra evaluate 的关系

`extra_evaluate` 继续保留。

但手动追加的结果需要明确标记：

1. 是否进入生态矩阵
2. 是否计入阵营统计
3. 是否进入四大分析区块

建议默认：

- 手动追加结果进入矩阵与明细
- 但不自动挤占首批自动 citation 的代表样本

## 9. 前端渲染改造建议

当前前端 `ConfidenceSignalContent` 的问题是：

1. 主视觉仍是排名页
2. brand / competitor 依赖前端关键词启发式
3. 没有矩阵
4. 没有象限
5. 没有四个深度分析区
6. 没有修我行动落地

### 9.1 新版组件拆分建议

建议在现有 `ConfidenceSignalContent.tsx` 下重构为：

1. `ConfidenceReportHero`
2. `ConfidenceEcosystemMatrix`
3. `ConfidenceQuadrantOverview`
4. `ConfidenceAnalysisBlock`
5. `ConfidenceGeneralKnowledgePanel`
6. `ConfidenceRepairActions`
7. `ConfidenceExtraComposer`

### 9.2 删除旧主结构

旧的两张核心表：

1. `涉及品牌相关内容链接的置信度排名`
2. `涉及竞品相关内容链接的置信度排名`

不再作为新版报告主结构。

它们最多只能退居为辅助明细，不应占据主版面。

## 10. UX 交互原则

### 10.1 用户首先看到生态，不是明细

打开报告后，第一眼必须先看到：

1. 总体结论
2. 生态矩阵
3. 四象限摘要

而不是一张长表格。

### 10.2 每个结论都要能落到动作

不能只说：

- `竞品这条内容分高`
- `我方这条内容分低`

必须接着说：

- 为什么高 / 低
- 对我方意味着什么
- 我接下来应该怎么修

### 10.3 用业务概念承接 AICE，而不是让 AICE 直接裸露

AICE 是底层判据，不是用户阅读主轴。

用户主轴应当是：

- 阵营
- 象限
- 原因
- 动作

AICE 维度细节放在：

1. 卡片二级展开
2. 详情抽屉
3. hover 说明

## 11. MVP 实施边界

本次重设计优先做“解释层重构”，不要求一步到位做完整分析系统。

### 11.1 MVP 必做

1. 保留当前 A7 `confidence_signal` artifact 类型
2. 新增 `entity_classification`
3. 新增 `quadrant`
4. 新增生态矩阵主视图
5. 新增四象限摘要
6. 新增四个核心分析区块
7. 新增修我行动清单

### 11.2 MVP 可暂缓

1. 复杂筛选器
2. 拖拽矩阵交互
3. 多轮比较版本
4. Dashboard 聚合化复用
5. 共业阵营的深层专题分析

---

## 12. 验收标准

新版置信度报告要满足以下验收：

### 产品验收

1. 用户能在 30 秒内理解“这不是评分表，而是一份 AI 语境生态报告”
2. 用户能明确区分我方 / 竞方 / 共业三类来源
3. 用户能理解四象限的业务含义
4. 用户能从报告中直接抽出优先修我动作

### UX 验收

1. 首屏不再是长表格
2. 用户阅读顺序为：总论 -> 矩阵 -> 象限 -> 深度分析 -> 动作
3. 详情解释与明细不会压过主结论

### 架构验收

1. 不新增一级页面
2. 不替换 AICE 评分引擎
3. 不替换 A7 Agent
4. 仅扩展 `confidence_signal` 的 payload 与渲染器

---

## 13. 联合结论

PM 结论：

- 该方案显著提升 A7 的产品价值密度，使其真正服务于“品牌在 AI 语境下的长期占位”。

UX 结论：

- 该方案把用户认知从“看链接分数”提升为“看语料生态与修我路径”，信息层级更清晰，决策路径更短。

架构结论：

- 该方案不要求推翻现有 A7，只需在现有 AICE 与 `confidence_signal` artifact 基础上扩展分类、分组、矩阵与行动合成逻辑，具备较好的实施可行性。
