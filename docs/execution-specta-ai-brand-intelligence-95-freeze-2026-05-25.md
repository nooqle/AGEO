# Specta AI 品牌情报 95% 功能清单与验收冻结版

日期：2026-05-25
状态：Frozen Scope
适用范围：`codex/specta-ontology-foundation` 本地 worktree
目标：把当前约 86% 的品牌情报系统推进到可称为 95% 的生产准备状态
非目标：本轮不合并 `main`，不部署线上，不新增主页签，不把 3D 视图作为默认主路径

## 0. 冻结结论

95% 不是继续堆页面、图表或视觉效果，而是让企业用户能稳定回答五件事：

1. 我的品牌在 AI 回答里表现如何。
2. 这个判断来自哪些样本和证据。
3. 我的品牌和竞品、平台、来源、问题之间是什么关系。
4. 我下一步该做什么，为什么值得做。
5. 做完以后，系统如何复查变化。

子智能体结论已合并：

| 角色 | 核心判断 | 对 95% 的约束 |
|---|---|---|
| PM | 客户付费买的是可信诊断、可追溯证据、商业解释、可执行任务、执行后复盘 | 每个结论必须可信，每个证据必须干净，每个建议必须能进入任务闭环 |
| UX | 用户必须 10 秒内看懂图谱在说什么、凭什么可信、下一步做什么 | 品牌世界不是装饰图；节点、连线、大小、颜色、距离都必须有业务含义 |
| QA | 当前 E2E 跑通只能证明主路径没坏，不能证明到 95% | 95% 必须覆盖低样本、慢网络、未认证、WebGL 失败、反馈失败、证据泄露等不友好条件 |

最终判断：95% 之前最重要的不是“更多功能”，而是把 Specta 从“能展示品牌情报”推进到“客户敢用它做品牌决策并持续跟进”。

## 1. 当前状态判断

当前约 86/100。分项判断如下：

| 模块 | 当前判断 | 主要差距 |
|---|---:|---|

| Dashboard 主路径 | 86% | 四页签可跑通，但首屏状态、页签闭环、业务优先级还不够强 |
| 品牌世界 2D/3D | 84% | 2D 默认路径可用，3D 视觉方向接近；节点商业解释仍不足 |

95% 的差距主要不是视觉，而是可信度、解释力、任务闭环和发布卫生。

## 2. 产品结构冻结

主信息架构保持四个页签，不再新增主页签：

| 页签 | 回答的问题 | 必须呈现 |
|---|---|---|
| 简要情报 | 品牌在 AI 世界里的表现如何 | AI 提及率、提及排名、官网引用率、语气性质、样本量、置信状态、优先行动 |
| 情报来源 | 这些判断从哪里来 | 平台、问题、回答摘录、引用来源、竞品排名、语气分布、样本质量 |
| 品牌世界 | 品牌、竞品、平台、来源、问题、建议之间是什么关系 | 默认 2D 业务图谱，二级 3D 探索视图，节点详情，关系解释，证据强度 |
| 跟进反馈 | 现在应该做什么，做完如何复查 | 建议任务、负责人、状态、截止时间、证据来源、预期影响、复查标准 |

四页签必须形成闭环：

```text
简要情报结论 -> 情报来源证据 -> 品牌世界关系 -> 跟进反馈任务 -> 下一轮复查
```

## 7. 文案与语言规则

这些规则同时适用于页面、空状态、按钮、提示、证据说明和图谱面板。

### 7.1 禁止出现

- 内部工程词：Ontology、ActionRecord、Orchestrator、weak relation、object graph、payload、runtime、debug。
- 自说自话文案：看重点、查证据、处理反馈、构建世界、这个很重要、点击展开研判。
- 模型过程痕迹：我将、首先我需要、作为 AI、推理过程、调用工具、websearch 工具、prompt、chain、trace。
- 不可验证承诺：一定提升、显著增长、保证进入 AI 答案。

### 7.2 推荐表达

| 不要写 | 推荐写法 |
|---|---|
| 直接连接 | 共同出现 / 共同被提及 / 竞争比较 |
| 指向 | 被比较 / 被引用 / 支持该判断 / 影响该主题 |
| 衡量 | 证据强度 / 可见度 / 相关度 |
| 证据样本 | 代表性证据 |
| 创建监测计划 | 打开监测设置 |
| 处理反馈 | 加入跟进 / 标记复核 / 记录处理结果 |
| 对象关系 | 品牌世界 |
| 弱关系 | 辅助线索 |

页面文案只回答三类问题：

1. 看什么。
2. 凭什么。
3. 下一步做什么。

## 8. 品牌世界验收定义

品牌世界的默认形态：

```text
中心：当前品牌
第一圈：提及率、排名、官网引用率、语气性质、竞品、AI 平台、引用来源、建议
第二圈：点击节点后展开对应平台、竞品、官网域名、外部来源、回答样本、建议任务
```

必须满足：

| 元素 | 业务含义 | 验收标准 |
|---|---|---|
| 节点大小 | 证据量或影响权重 | 图例解释清楚；不能只靠视觉猜 |
| 节点颜色 | 类型或状态 | 品牌、竞品、平台、来源、指标、建议有稳定颜色语义 |
| 节点距离 | 关系强弱或相关程度 | 距离近必须能在详情中解释 |
| 连线 | 关系类型 | 点击连线能说明为什么存在这条关系 |
| 2D 视图 | 默认工作视图 | 桌面和移动都可读、可点、可返回 |
| 3D 视图 | 探索视图 | 可旋转、缩放、退出；失败回退 2D |
| 详情面板 | 商业解释 | 展示关系类型、证据强度、来源、影响和建议 |

品牌世界不展示对象清单墙，不默认展示辅助关系，不用技术词解释图谱。

## 9. 跟进反馈验收定义

跟进反馈不是静态建议列表，而是商业执行入口。

建议必须落到具体动作：

| 建议类型 | 示例内容方向 | 必须绑定 |
|---|---|---|
| 开启周期监测 | 对高价值问题和竞品组合做周度复查 | 指标、样本、复查周期 |
| 补官网证据页 | 针对官网未被引用，补充可被 AI 摘取的优势、参数、案例、FAQ | 官网引用率、外部来源、缺口主题 |
| 补竞品同场问题 | 对排名样本不足或竞品样本缺失，补充同场景问题 | 排名、竞品、问题类型 |
| 处理负向提及 | 对负向或模糊回答，拆出原因并补内容 | 语气性质、回答摘录、来源 |
| 优化外部来源 | 针对高频来源站点，规划内容投放或公关材料 | 来源域名、平台偏好、内容方向 |

每条任务必须包含：

- 状态：待处理、进行中、已完成、待复查。
- 负责人：可以为空，但必须有字段。
- 截止时间：可以为空，但必须有字段。
- 证据来源：来自哪个指标、问题、回答或来源。
- 预期影响：预计影响提及率、排名、官网引用率还是语气性质。
- 复查标准：下一轮如何判断有效。

## 10. QA 验收用例

| 用例 | 步骤 | 期望 |
|---|---|---|
| 桌面主路径 | 进入理想汽车报告，依次打开四页签 | 每页稳定渲染，无严重控制台错误 |
| 移动主路径 | 375px 视口进入品牌世界 | 默认 2D 可读、可点、可返回 |
| 加载状态 | 慢网速或接口延迟打开简要情报 | loading 期间不显示错误 0 值 |
| 空数据品牌 | 使用低样本或无样本品牌 | 显示暂无数据或样本不足，不伪造排名 |
| 排名可信度 | 查看排名指标和情报来源排名 | 显示样本量、来源、时间范围、低样本提示 |
| 证据清洁 | 抽查 50 条证据 | 无 prompt、推理链、debug、模型过程、问号占位符 |
| 2D 节点点击 | 点击品牌、竞品、来源、主题、指标节点 | 展示关系解释、证据、建议动作 |
| 3D 正常路径 | 进入 3D，旋转、缩放、返回 | 不白屏，不丢品牌上下文 |
| 3D 降级 | 禁用或模拟 WebGL 失败 | 自动回退 2D，有非技术化提示 |
| 反馈成功 | 提交一条跟进反馈 | 成功状态可见，刷新后仍可确认 |
| 反馈失败 | 模拟 500 或网络失败 | 不丢输入，可重试，有错误提示 |
| 未认证访问 | 清 token 直连 API 或页面 | API 403，前端引导登录，不泄露数据 |
| 过期认证 | 使用过期 token 打开报告 | 有清晰重登路径，无无限 loading |
| 回归巡检 | build 后跑核心 E2E 和截图对比 | 四页签关键截图无重大布局退化 |

## 11. Release Gate

95% 发布准备必须按门禁通过，不能靠主观判断。

| Gate | 通过标准 |
|---|---|
| Gate 1 仓库卫生 | `git status` 中所有未跟踪文件都有归属；发布分支、变更范围、迁移文件清楚 |
| Gate 2 静态验证 | `npm run lint`、`npm run build`、`python scripts/validate_change.py` 通过；无新增问号占位符 |
| Gate 3 后端测试 | 品牌提及、world projection、ontology API、action strict、监测入口、权限负向测试通过 |
| Gate 4 前端 E2E | 桌面四页签、移动 2D 图谱、3D 探索、认证状态、反馈状态通过 |
| Gate 5 数据可信度 | 0 值闪烁、低样本排名、证据来源、过程泄露均有截图或抽查证据 |
| Gate 6 降级路径 | WebGL 失败、接口失败、反馈失败、权限失败都有可恢复 UI |
| Gate 7 安全 | high/critical 依赖告警处理，或有明确风险接受人、影响范围和延期日期 |
| Gate 8 发布前复核 | P0 = 0；P1 要么关闭，要么有书面豁免；P2 进入后续清单 |
| Gate 9 发布后冒烟 | 生产入口、登录、四页签、品牌世界、反馈提交各跑一次 |

## 12. 不做清单

95% 之前不做：

- 不新增主页签。
- 不把 3D 设为默认主视图。
- 不继续堆无明确商业问题的图表。
- 不做更多粒子、光效、镜头飞行、星云背景。
- 不做多套主题或暗色宇宙模式。
- 不做复杂团队协作权限。
- 不做高级导出和客户 logo 定制。
- 不用更长的 AI 总结替代证据和任务。
- 不隐藏样本不足。
- 不把“监测计划创建”放回 Chat 主路径。

## 13. 后续实施顺序

### Sprint A：可信度底座

目标：用户看到的指标和证据可信。

1. 修复加载 0 值闪烁。
2. 所有指标补样本量、平台、时间范围、低样本降级。
3. 清理证据样本中的模型过程痕迹。
4. 补齐证据抽查脚本或人工抽查清单。

完成标准：简要情报和情报来源不再误导用户，不再出现过程泄露。

### Sprint B：品牌世界语义闭环

目标：图谱可解释、可行动。

1. 品牌世界加图例和业务语义。
2. 核心节点详情面板改成关系解释、证据、建议动作。
3. 2D/3D 选中状态一致。
4. WebGL 失败回退 2D。

完成标准：点击任一核心节点后，用户能知道它是谁、为什么重要、证据在哪里、下一步做什么。

### Sprint C：跟进反馈任务闭环

目标：建议变成可复查的执行任务。

1. 建议增加状态、负责人、截止时间、证据来源、预期影响、复查标准。
2. 反馈提交成功、失败、刷新后状态完整。
3. 任务和简要情报、情报来源、品牌世界建立返回路径。
4. 监测入口统一打开设置里的监测功能。

完成标准：用户不只是看报告，而是能进入持续优化工作流。

### Sprint D：发布收口

目标：从可演示进入可发布。

1. 处理或登记依赖安全告警。
2. 解释并清理未跟踪文件。
3. 跑完整后端、前端、E2E、截图验证。
4. 完成 P0/P1/P2 状态表。

完成标准：P0 清零，P1 有明确状态，Release Gate 可逐项打勾。

## 14. 95% 判断标准

达到 95% 的判断不是“页面看起来不错”，而是：

- 品牌负责人 30 秒内能知道当前最大问题和下一步。
- 任一结论都能追溯到样本、平台、问题、回答和来源。
- 任一核心关系都能解释商业含义。
- 任一建议都能变成可管理、可复查的任务。
- 低样本、慢网络、未认证、WebGL 失败、反馈失败时，用户不会被误导、不会卡死、不会看到内部过程。
- 团队可以用同一套 Release Gate 防止回归。

如果以上有任一 P0 不满足，就不能称为 95%。
