# Specta AI 品牌情报 95% 生产级执行计划（2026-05-24）

> 状态：Execution Plan
> 范围：本地 `codex/specta-ontology-foundation` worktree。
> 目标：把当前 AI 品牌情报系统从“可演示”推进到“可生产验收”的 95% 状态。
> 非目标：本轮不合并 `main`，不部署线上，不重做 `imspecta.com` 视觉和交互。

## 一句话目标

Specta 要让品牌、增长和内容团队在一个品牌主页里完成这条链路：

```text
看现状 -> 查证据 -> 理解关系 -> 生成优化内容 -> 开启监测 -> 复查变化
```

95% 生产级不是页面更复杂，而是用户能相信数据、复核证据、采取动作，并在下一轮监测里看到变化。

## 当前验收结论

两轮 E2E 已确认当前仍有生产级阻塞：

1. 同一品牌页存在多套指标口径：`15.0%`、`68.75%`、`48/60`、`714/821` 混用。
2. 官网引用率归因不可信：`li.auto` 被当作官网，但 `lixiang.com` 出现在外部来源里。
3. 提及排名过度确定：竞品样本不足时仍显示 `第 1 / 12`。
4. Chat handoff 会污染旧会话，出现旧指标、旧 Round、内部阶段词。
5. 品牌世界是图谱雏形，但还不能从指标一路追到问题、回答、提及片段和引用来源。
6. 优化建议已有商业方向，但还需要绑定指标、证据、投放位置、内容方向和监测入口。

这些问题的共同根因是：业务事实、指标投影、界面入口和动作闭环还没有完全围绕同一套品牌世界运行。

## 95% 生产级定义

### 1. 5 秒内看懂现状

品牌主页首屏必须展示同一口径下的四个核心指标：

1. AI 提及率。
2. 提及排名。
3. 官网引用率。
4. 语气性质。

每个指标必须附带样本范围：时间、平台数、问题数、有效回答数、引用数。

### 2. 30 秒内追溯证据

用户点击任一指标后，必须能看到：

1. 分子和分母。
2. 计入样本。
3. 排除样本。
4. 平台拆分。
5. 问题和回答样本。
6. 引用来源。
7. 语气片段。

用户不需要读文档就能复算指标。

### 3. 1 次点击理解关系

品牌世界不是对象清单，也不是摘要卡片。它必须展示：

```text
品牌
  -> 指标
  -> AI 平台
  -> 用户问题
  -> AI 回答
  -> 品牌提及事实
  -> 引用来源
  -> 竞品
  -> 优化建议
```

点击节点后，右侧详情必须说明：

1. 这个节点是什么。
2. 它和品牌是什么关系。
3. 它支撑哪个指标。
4. 有哪些证据。
5. 下一步能做什么。

### 4. 建议可执行

每条优化建议必须回答：

1. 为什么要做。
2. 影响哪个指标。
3. 哪些证据支撑。
4. 做什么内容。
5. 投到哪里。
6. 是否进入周期监测。

建议必须能转成内容生产或监测设置，而不是停留在泛泛描述。

### 5. Chat 是解释和协作入口

Chat 不再是唯一主流程入口。它只承接当前品牌、当前指标、当前证据或当前建议：

1. 解释这个指标。
2. 解释这段关系。
3. 补证。
4. 改稿。
5. 生成内容草稿。

Chat handoff 必须干净，禁止混入旧会话、旧指标、内部阶段词和调试信息。

## P0 Release Gate

P0 是发布闸门。以下问题未修复前，不能称为生产级。

### P0-1 指标口径统一

问题：

```text
同一品牌页同时出现 15.0%、68.75%、48/60、714/821。
```

业务影响：用户无法判断理想汽车在 AI 世界里的真实表现。

解决原则：

1. Dashboard、world API、情报来源、Chat handoff 使用同一套权威 `summary_projection` / `evidence_projection`。
2. 如果历史报告或监测结果使用不同口径，必须明确标记为历史结果，不得混入当前首屏结论。
3. 每个指标展示同一个样本范围。

验收标准：

1. 理想汽车当前页面所有入口的提及率一致。
2. 样本范围一致。
3. 引用总数一致。
4. Chat handoff 中的样本摘要与 Dashboard 当前口径一致。

### P0-2 官网域名归因

问题：

```text
官网引用率显示 0.0%，但外部来源中出现 lixiang.com。
```

业务影响：系统会把可能属于品牌官网的引用误判为外部来源。

解决原则：

1. 品牌必须有官方域名别名集合。
2. `li.auto`、`lixiang.com`、`www.lixiang.com` 等归入同一官方资产。
3. 官网引用率、外部来源排行、图谱来源节点都使用同一归因函数。

验收标准：

1. `lixiang.com` 不再作为理想汽车外部来源展示。
2. 官网引用次数包含官方别名域名。
3. 页面能说明本轮哪些官方域名被计入。

### P0-3 排名可信度

问题：

```text
竞品样本不足时显示“第 1 / 12”。
```

业务影响：销售演示中会被理解为虚假领先。

解决原则：

1. 提及排名必须有样本充分性。
2. 如果竞品提及均为 0 或竞品答案不足，不显示确定性排名。
3. 前端展示“竞品样本不足”或“排名未形成”，并给出补样建议。

验收标准：

1. 理想汽车竞品全 0 时不再显示确定排名。
2. 排名详情说明当前样本是否足以比较。
3. 优化建议能提示补竞品同场问题。

### P0-4 Chat handoff 去污染

问题：

```text
从 Dashboard 进入 Chat 后，旧会话历史、旧指标、Round 和内部阶段词会混入当前任务。
```

业务影响：用户会基于错误上下文做判断。

解决原则：

1. Dashboard handoff 使用当前品牌世界投影生成干净上下文。
2. 新 handoff 不复用旧指标和旧报告作为首屏判断。
3. 用户可见首屏禁止内部词。

验收标准：

1. 点击“生成内容草稿”后，输入框只含当前理想汽车、当前指标、当前证据和当前建议。
2. 首屏不出现 `Round`、`A1-A4`、旧提及率、旧报告、其他品牌。
3. Chat 角色清晰：解释、补证、改稿，不是从零启动旧分析流程。

## P1 生产体验

### P1-1 情报来源自证

每个指标详情固定为：

```text
计算口径
样本范围
平台拆分
问题与回答样本
引用来源
排除项
```

回答正文默认折叠，用户点击后再展开。

### P1-2 品牌世界图谱升级

图谱默认显示中心品牌和第一圈强关系。点击第一圈后展开第二圈：

| 第一圈 | 第二圈 |
| --- | --- |
| AI 提及率 | 平台、问题、提及回答、未提及回答 |
| 提及排名 | 竞品、各竞品提及率、样本充分性 |
| 官网引用率 | 官方域名、疑似官网、外部来源 |
| 语气性质 | 正向、中性、负向回答样本 |
| AI 平台 | 平台级指标、问题分布 |
| 引用来源 | 域名、URL、引用次数 |
| 优化建议 | 内容方向、投放位置、监测指标 |

### P1-3 移动端首屏

`390x844` 首屏必须看到：

1. 品牌名。
2. 时间和样本范围。
3. 四个核心指标。
4. 四个页签入口。

用户不应先滚过品牌列表或大面积空白。

### P1-4 Settings 监测口径对齐

从建议进入 Settings 时：

1. 自动带上品牌。
2. 自动带上指标。
3. 自动带上问题和平台范围。
4. 当前看板样本和历史监测结果分开展示。

## P2 商业化增强

### P2-1 优化建议内容化

每条建议必须具备：

1. 内容方向。
2. 目标平台或来源。
3. 生成草稿要求。
4. 证据依据。
5. 预期影响指标。
6. 监测方式。

示例：

```text
补官网证据页
影响指标：官网引用率、AI 提及率
证据原因：本轮官方域名引用偏低，外部来源集中在汽车垂直站。
内容方向：增程技术、家庭用车、智能座舱、售后服务。
投放位置：官网知识页、懂车帝、汽车之家。
下一步：生成官网证据页草稿，建立周期复查。
```

### P2-2 导出和协作

生产级产品需要支持导出：

1. 当前指标摘要。
2. 证据包。
3. 优化建议。
4. 监测设置摘要。

本轮可以先留接口和文案，不作为 P0。

### P2-3 变化归因

周期监测后必须能说明：

1. 哪些指标变化。
2. 哪些问题变化。
3. 哪些来源变化。
4. 哪些内容动作可能影响了变化。

## 分阶段执行顺序

### 阶段 1：可信度地基，目标 65%

1. 统一指标口径。
2. 修复官网域名归因。
3. 修复排名可信度。
4. 修复 Chat handoff 污染。

### 阶段 2：证据自证，目标 78%

1. 指标详情补齐分子、分母、平台拆分。
2. 回答样本和引用来源进入可折叠证据抽屉。
3. 排除样本可见。

### 阶段 3：品牌世界图谱，目标 86%

1. 图谱节点加入问题、回答、提及事实、引用来源。
2. 右侧详情显示证据和关系动词。
3. 移动端改为图谱预览加节点详情列表。

### 阶段 4：商业化建议，目标 91%

1. 建议绑定指标。
2. 建议绑定证据。
3. 建议提供内容方向、投放位置和草稿要求。
4. Chat 只用于解释、补证、改稿。

### 阶段 5：监测闭环，目标 95%

1. 从建议进入 Settings 监测区。
2. 自动预填品牌、指标、问题和平台。
3. 建立优化前 baseline。
4. 支持复查变化。

## E2E 验收用例：理想汽车

### 用例 1：看现状

打开 Dashboard，选择理想汽车。

通过标准：

1. 首屏显示四个核心指标。
2. 四个指标样本范围一致。
3. 不出现旧指标冲突。

### 用例 2：查证据

点击 AI 提及率。

通过标准：

1. 显示分子、分母。
2. 显示平台拆分。
3. 显示提及回答和未提及回答。
4. 用户能复算提及率。

### 用例 3：查官网引用

点击官网引用率。

通过标准：

1. 显示官方域名集合。
2. `lixiang.com` 归入官方域名，不再出现在外部来源。
3. 显示外部来源排行。

### 用例 4：看品牌世界

进入品牌世界，点击 AI 平台、官网引用率、提及排名。

通过标准：

1. 图谱能展开第二圈。
2. 右侧详情能解释节点与品牌的关系。
3. 节点能进入证据或建议。

### 用例 5：生成内容建议

进入优化建议，打开草稿要求。

通过标准：

1. 每条建议有目标指标。
2. 每条建议有证据原因。
3. 每条建议有内容方向和投放位置。
4. 不出现内部术语。

### 用例 6：开启监测

点击打开监测设置。

通过标准：

1. 进入 Settings 监测区。
2. 品牌、指标、问题范围已预填。
3. 当前看板样本和历史监测结果不混用。

### 用例 7：Chat 解释

从某个指标或建议进入 Chat。

通过标准：

1. Chat 输入框只包含当前品牌、当前指标、当前证据。
2. 首屏不出现旧 Round、旧指标、内部阶段词。
3. Chat 只承担解释、补证、改稿。
