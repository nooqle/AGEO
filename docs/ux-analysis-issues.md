## Issue #4: 全景基线分析流程

### 4.1 现状分析

当前流程：用户创建品牌 → 进入聊天页 → 手动输入品牌名 → A1 品牌分析 → A2 画像 → 用户选择画像 → A3 模拟问题 → A4 抓取 → A5 报告。整个过程是**线性单次**的，没有"基线"与"场景细化"的区分。

**核心问题**：
- 用户首次进入后，没有明确引导告知"先跑基线，再做场景"
- 所有数据混在一起，无法区分全景数据和特定场景数据
- 无法独立查看"基线报告"和"场景报告"

### 4.4 需要向产品确认的问题

1. **基线问题来源**：全景基线的问题是否由 A3 直接根据品牌+行业生成（不经过 A2 画像），还是使用一组固定的通用问题模板？
2. **自动触发 vs 手动触发**：创建品牌后是否完全自动开始基线分析，还是先展示品牌信息让用户确认后再开始？

5. **Dashboard 当前结构**：目前 Dashboard 主要是品牌列表+创建入口，尚无数据展示区域。Issue #4 的 Dashboard 分区是否作为 P1 后续需求，还是和基线流程一起做？

## Issue #5: 交付物导航合并与历史回溯

### 5.1 现状分析

**当前问题**：
- `canvasStore.ts` 中 `contents` 是一个扁平数组，每个交付物都是独立条目
- 多次执行同类型操作（如两次 A4 抓取）会在 ArtifactNav 中产生两个独立的"抓取"条目
- 用户无法区分它们（标题可能相同或相似）
- ArtifactNav compact 模式只显示 icon + 类型文字，没有时间/版本信息
- CanvasContent 类型定义中有 `relatedMessageId` 字段，但目前在加载时设为空字符串

**ArtifactNav 当前渲染逻辑** (`ArtifactNav.tsx`):
- 直接遍历 `contents` 数组，每个 content 一个按钮
- compact 模式：icon + 类型标签（报告/图表/问题/抓取等）
- full 模式：icon + title + 类型标签

### 5.2 交互设计方案

#### 方案：按类型分组 + 版本下拉

将同类型的交付物合并为一个导航入口，点击展开显示历史版本列表。

### 5.3 "跳转到对话上下文" 交互

**实现思路**：
- 每个 CanvasContent 已有 `relatedMessageId` 字段
- 点击版本列表中的 [跳转对话] 按钮：
  1. 关闭或缩小 Canvas
  2. 在 ChatPanel 的消息列表中滚动到对应的 message
  3. 该消息短暂高亮闪烁（2秒淡入淡出），帮助用户定位

**交互流程**：
```
用户在 Canvas 版本列表点击 [跳转对话 ↗]
  │
  ├─ Canvas 保持打开（split 模式下不关闭）
  │
  ├─ ChatPanel 平滑滚动到 relatedMessageId 对应的消息
  │
  └─ 目标消息添加临时高亮样式：
     - 浅色背景闪烁 (品牌色 6% 透明度)
     - 左侧出现 2px 品牌色竖线
     - 2 秒后渐隐
```

### 5.5 需要向产品确认的问题

1. **分组粒度**：是否仅按 `type` 分组？还是需要更细粒度（例如区分"基线报告"和"场景报告"，即使都是 `report` 类型）？
2. **版本删除**：用户是否可以删除单个历史版本？
3. **跳转对话的前置条件**：`relatedMessageId` 当前在历史加载时为空字符串。需要后端在 `output_ready` 事件中传递对应的 message_id，或在 API 的 output 数据中关联 message_id。这是否需要后端配合？

## Issue #6: 浅色模式全面验收

### 6.1 CSS 变量覆盖评估

当前 `globals.css` 中已定义 `html[data-theme="light"]` 覆盖块，覆盖了：
- 背景层级 (bg-primary/secondary/tertiary/elevated/card) -- **完整**
- 文字层级 (text-primary/secondary/tertiary/disabled/muted) -- **完整**
- 边框 (border-default/hover/focus) -- **完整**
- 品牌色 (brand-primary/hover/active, color-primary 系列) -- **完整**
- 语义色 (success/warning/error/info + 对应 bg) -- **完整**
- TPAOR 阶段色 -- **完整**
- 阴影 (shadow-sm/md/lg/glow) -- **完整**
- Glass morphism -- **完整**

**评价**：变量覆盖层面做得相当完整。

### 6.2 需要检查的问题清单

以下是基于代码审查发现的潜在问题：

#### A. 硬编码颜色值（未使用 CSS 变量）

| 位置 | 问题 | 影响 |
|------|------|------|
| `CanvasPanel.tsx:25` | `shadow-[-4px_0_24px_rgba(0,0,0,0.4)]` | 浅色模式下阴影过重，应减弱 |
| `CanvasPanel.tsx:89` | 同上 shadow | 同上 |
| `MessageList.tsx:84` | `bg-gradient-to-br from-indigo-500 to-purple-600` | Tailwind 硬编码色值，但作为 logo/品牌色可接受 |
| `MessageList.tsx:102` | `hover:border-[#6366F1]` | 硬编码品牌色，但浅色下视觉一致，影响小 |
| `CanvasHeader.tsx:110-114` | `text-indigo-400`, `text-blue-400`, `text-purple-400` | Tailwind 类名，浅色模式下应调深一个等级 |
| `ChatPanel.tsx:422` | `bg-black/60 backdrop-blur-sm` | 确认弹窗遮罩，浅色下黑色遮罩可能不协调 |

#### B. 组件级美化建议

| 组件 | 当前问题 | 建议 |
|------|----------|------|
| **CanvasPanel 空状态** | 背景单调，icon 偏暗 | 浅色下 icon 使用 text-tertiary (#6B7280) 已可接受；增加一个淡灰背景圆 |
| **CanvasPanel 阴影** | `rgba(0,0,0,0.4)` 在浅色下过重 | 浅色模式下改为 `rgba(0,0,0,0.08)` |
| **InputArea 输入框** | 圆角+边框已有，但浅色下缺乏层次 | bg-secondary 在浅色下是 #FFFFFF，与 bg-primary #F4F4F5 几乎一致，需微调 |
| **ChatSidebar** | Entity 列表悬停态在浅色下可能不明显 | bg-tertiary (#F0F0F0) vs bg-primary (#F4F4F5) 差异太小 |
| **CanvasTabs** | border-b 使用 `border-[--border-default]` 正确 | OK |
| **ConfirmationCard 遮罩** | `bg-black/60` 在浅色下过暗 | 浅色改为 `bg-black/40` 或用 `bg-white/70 backdrop-blur` |
| **ScrollBar** | 深色下 `::-webkit-scrollbar-thumb: var(--border-hover)` | 浅色下 #D4D4D8 可接受，但可以更浅 |

#### C. 呼吸感优化（全局）

| 区域 | 建议 |
|------|------|
| **ChatPanel 消息间距** | 当前 `space-y-6`（24px）合适 |
| **消息内容区** | `max-w-3xl mx-auto px-4 py-6`，浅色模式下建议增加 `px-6` |
| **Canvas Header** | `px-4 py-3` 稍紧凑，建议 `py-4` |
| **ArtifactNav compact** | 按钮间距 `gap-1`（4px）太紧，建议 `gap-1.5`（6px）|
| **Sidebar Entity Card** | `p-3` 内边距 OK，但 `mb-2` 间距小，建议 `mb-2.5` |
| **整体字重** | 浅色模式下文字应略重，h2/h3 使用 font-semibold (600) 已 OK |

#### D. 主题切换过渡

当前已有 `html.theme-transitioning` 的过渡动画定义（200ms ease-out），覆盖了 background-color / border-color / color / box-shadow。**这部分做得很好**。

### 6.3 浅色模式验收 Checklist

### 6.4 关键原则

1. **浅色模式不是简单取反** — 不是把白变黑、黑变白。浅色模式下阴影应更轻、文字对比度保持 WCAG AA (4.5:1)、品牌色可以略深。
2. **呼吸感来自留白** — 不是增加装饰，而是增加 padding/margin/gap，让元素之间有足够间距。
3. **层次感** — 浅色下 bg-primary (#F4F4F5) vs bg-secondary (#FFFFFF) 差异仅 11 个灰度值，可以考虑加大到 bg-primary: #F0F1F3 或 bg-secondary 增加微弱阴影。
