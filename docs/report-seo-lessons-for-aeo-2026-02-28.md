## 一、SEO 行业走过的路：三个关键历史阶段

### 1.1 SEO 如何采集数据？——从来就没有"官方API"

这是最重要的一个事实：

> **Google 从未提供过 SERP（搜索结果页）排名查询的官方 API。**

Ahrefs、SEMrush 这些年收入数亿美金的 SEO 巨头，从第一天起就是靠**爬虫抓取**（也就是我们说的"浏览器方式"）来获取数据的。它们的做法是：

| 做法 | 细节 |
|------|------|
| **大规模代理网络** | 数千台代理服务器，分布在全球各地 |
| **模拟真人行为** | 随机延迟、随机访问首页、模拟鼠标移动 |
| **数据中心级基础设施** | 自建数据中心，持续扩容 |
| **和Google"斗智斗勇"** | Google 会反爬，SEO工具就不断升级绕过手段 |

2025年9月，Google 甚至取消了 `&num=100` 参数（原本可以一次查100条结果），强迫 SEO 工具必须发10次请求才能获取同样的数据——**运营成本一夜之间翻了10倍**。

但 Ahrefs 在一个月内就恢复了 Top 100 追踪能力。

**这说明什么？** Browser/爬虫采集虽然困难、昂贵、复杂，但这是 SEO 行业**唯一的数据获取方式**，整个数百亿美金的产业就是建立在这个基础上的。

> 来源：[Ahrefs restores top 100 search result tracking after Google parameter restrictions](https://ppc.land/ahrefs-restores-top-100-search-result-tracking-after-google-parameter-restrictions/)、[How do Ahrefs, SEMrush scrape Google?](https://www.quora.com/How-do-Ahrefs-SEMrush-or-other-services-scrape-Google-results-while-gathering-billions-of-keywords-without-getting-blocked)

### 1.2 搜索结果个性化来了——SEO 死了吗？

2009年，Google 开始全面推行**个性化搜索**。当时 SEO 行业的恐慌和我们今天讨论的"如果AI个性化了怎么办"如出一辙。

**个性化的影响到底有多大？**

| 个性化因素 | 影响方式 |
|-----------|---------|
| 搜索历史 | 你之前搜过什么，会影响后续结果排序 |
| 地理位置 | 同一个搜索词，北京和上海看到的结果不同 |
| 浏览历史 | 你常访问哪些网站，这些网站排名会提升 |
| 登录状态 | 登录Google账号 vs 未登录，结果有差异 |
| Cookie记录 | 即使未登录，Google也通过180天的Cookie追踪行为 |

2024年11月，Google Core Update 被发现**进一步加深了个性化**——登录用户和匿名用户看到的搜索结果、视频框、排名都有明显差异。SEO 工具报告的数据和 Google Search Console 的数据也出现了偏差。

> 来源：[Google Search Personalization And Its Impact On SEO In 2024](https://williamsmedia.co/google-search-personalization)、[Is Google Personalizing Search Results More Than Ever?](https://www.stanventures.com/news/is-google-personalizing-search-results-more-than-ever-1335/)

**但是——SEO 不但没死，反而爆发了：**

| 指标 | 数据 |
|------|------|
| SEO 全球市场规模（2025） | **$749亿** |
| 预计规模（2030） | **$1,273亿**，CAGR 12-17% |
| SEMrush 年收入（2024） | **$3.77亿**，YoY +22% |
| Ahrefs 年收入（2024） | **$1.49亿**，YoY +49% |
| SEO 从业者认为 SEO 有正面效果 | **91%** |

> 来源：[SEO Services Market Projected to Reach $171.77B by 2030](https://www.prnewswire.com/news-releases/search-engine-optimization-seo-services-market-projected-to-reach-usd-171-77-billion-by-2030--growing-at-13-24-cagr-markntel-advisors-top-companies---semrush-holdings-inc-ahrefs-pte-ltd-moz-group-llc-302505098.html)、[How Ahrefs hit $149.1M revenue](https://getlatka.com/companies/ahrefs)

### 1.3 SEO 是怎么活下来的？三个关键转型

**转型一：从"精确排名"到"可见度概率"**

早期 SEO 说"你的网站在'护肤品推荐'这个词上排第3"。个性化之后，不同人看到的排名不同了。

行业的应对：不再追踪一个固定名次，而是追踪**"在1000次搜索中，你出现在前10的概率是多少"**。

**转型二：从"单一视角"到"多视角"**

SEO 工具开始从不同地区、不同设备、登录/未登录等多个维度采集数据，给出**分布式的可见度图谱**而非单一排名数字。

**转型三：从"排名优化"到"内容质量（E-E-A-T）"**

Google 越来越强调 E-E-A-T（经验、专业、权威、信任），纯粹的技术优化失效了，内容质量成为核心。SEO 工具也从"帮你提排名"转型为"帮你诊断内容质量、找到优化方向"。

## 二、AEO 行业现在在做什么？——竞品真实分析

### 2.1 行业龙头 Profound：明确选择了 Browser

Profound 是目前 AEO 赛道的领头羊——2025年完成 **$3,500万 B轮融资**，投资方是**红杉资本**。

他们的数据采集方法论值得我们仔细研究：

| 方法 | 细节 |
|------|------|
| **前端抓取（Front-end Scraping）** | 每天向10+个AI引擎发送**600万条提示词**，捕获浏览器端的真实回答 |
| **明确拒绝 API** | 官方表述："追踪真实用户看到的内容，而非净化过的API响应" |
| **真实用户对话数据** | 通过合规数据面板获取**1.3亿条**真实用户对话 |
| **服务端日志分析** | 接入 Cloudflare/Vercel 等CDN，分析 AI 爬虫如何访问网站 |
| **覆盖引擎** | ChatGPT, Perplexity, Google AI, Gemini, Claude, DeepSeek, Grok, Copilot, Meta AI（10+） |

**关键洞察：Profound 明确选择了"浏览器端采集"路线，并且把"不用 API"作为差异化卖点。这和我们的实测发现完全吻合——API 和 Browser 的回答确实不同，Profound 认为 Browser 才是真相。**

## 三、AI 个性化：正在发生什么？

### 3.1 已经落地的个性化功能

| 平台 | 功能 | 时间 | 影响 |
|------|------|------|------|
| **ChatGPT** | Memory with Search | 2025年4月 | 基于历史对话个性化搜索结果 |
| **ChatGPT** | 个性化人格设置 | 2025年 | Plus/Pro用户可自定义回答风格 |
| **Google AI Mode** | 深度个性化 | 2025年夏 | 基于搜索历史、应用、Drive、Gmail |
| **Gartner 预测** | 传统搜索量下降25% | 到2026年 | 用户转向AI助手 |

### 3.2 学术界的个性化研究方向

最新论文（arXiv 2502.11528）总结了 LLM 个性化的三大技术路线：
- **Cue-CoT**：从历史对话中提取用户情绪、性格、心理状态，用于个性化回答
- **ONCE**：从浏览历史总结用户兴趣区域，增强个性化推荐
- **用户画像增强**：将用户档案直接注入提示词，改变生成策略

> 来源：[A Survey of Personalized Large Language Models](https://arxiv.org/html/2502.11528v2)、[ChatGPT Memory with Search (TechCrunch)](https://techcrunch.com/2025/04/18/chatgpt-will-now-use-its-memory-to-personalize-web-searches/)

### 3.3 对 AEO 的影响预判

基于 SEO 行业的经验，我们可以做出以下推断：

**短期（6-12个月）：影响很小**
- 目前 AI 个性化仅限于"记忆偏好 + 风格调整"，尚未深入到"推荐不同品牌"的程度
- 大多数用户使用默认设置，不配置个性化
- 中国AI平台（Kimi、豆包、DeepSeek）的个性化程度远低于 ChatGPT

**中期（1-2年）：开始出现分化**
- 高频用户的回答会和新用户产生差异
- 但和搜索类似，核心推荐（前3位品牌）大概率保持稳定
- 差异主要体现在长尾推荐和回答风格上

**长期（2-3年+）：需要范式升级**
- 从"你排第几"→"你在多大比例的对话中被提及"
- 从"统一排名"→"分人群可见度"
- 但这恰恰是商业价值更大的方向（后面详述）

## 四、团队辩论：Browser 的战略定位

### 正方（产品经理）：Browser 必须是主力，这不是选择题

**论据一：行业标准已经确立**

Profound 拿到红杉 $3500万投资，核心方法论就是"前端抓取，不用API"。我们的实测数据（API vs Browser 约50%重叠）证实了这个选择的合理性。如果我们继续用 API 作为主力，产出的数据和用户实际体验对不上，这是一个根本性的信任问题。

**论据二：品牌方买的是"消费者看到什么"**

品牌方关心的不是"AI模型的底层知识是什么"，而是**"当消费者在豆包上搜'抗蓝光护肤品'时，看到的是哪些品牌"**。API返回的答案是一个技术中间层，不是消费者体验层。

**论据三：个性化时代更需要 Browser**

ChatGPT 已经推出了 Memory with Search，Google AI Mode 即将全面个性化。未来唯一能观察"不同画像用户看到什么"的方式就是通过浏览器模拟不同用户身份。API 是看不到个性化效果的。

**但是——这不意味着明天就要全切 Browser：**

SEMrush 花了 15 年才建起今天的爬虫基础设施。我们是初创公司，不能一步到位，但方向必须明确。

### 反方（架构师）：Browser 有三大未解难题，不能盲目 all-in

**难题一：速度——10倍的差距不是小问题**

| 场景 | API | Browser |
|------|-----|---------|
| 单次查询 | 3-10秒 | 20-70秒 |
| 完整分析（80次查询） | ~10分钟 | ~60-90分钟 |
| 用户体验感受 | "几分钟出报告" | "等一个多小时" |

用户不会等一个小时出报告。这不是优化能解决的——浏览器本身的渲染、等待AI生成、网络延迟就决定了下限。

**难题二：稳定性——脆弱的 DOM 依赖**

我们的 Kimi 和豆包测试中，已经遇到了：
- 豆包登录4次后要求重新认证
- Q9/Q10 创建了 local_ 离线会话导致失败
- DOM 选择器随平台更新随时可能失效
- 不同时段、不同地区的页面结构可能不同

SEO 工具爬 Google 有一个优势：Google SERP 的 HTML 结构相对稳定。但 AI 聊天界面是富交互应用，DOM 变化频繁得多。

**难题三：规模化成本**

如果要做到 Profound 的水平（每天600万次查询），按我们当前的 Browser 架构：
- 需要约 **200-500台** 云主机并行（按 70秒/次、24小时运行计算）
- 每月云服务成本约 **$20,000-$50,000**
- 还需要账号池管理、反检测、DOM维护等运营开销

**架构师的建议：分阶段演进**

```
Phase 1（现在 → 3个月）: API 为主力 + Browser 定期校准
  - 日常监测用 API（快速、稳定）
  - 每周/每次报告前用 Browser 做小样本对比
  - 建立两者的偏差映射模型
  - 成本低，风险可控

Phase 2（3-6个月）: Browser 比重逐步上升
  - 投入 3-5 台云主机做 Browser 集群
  - 支持 4 平台并行采集
  - 引入"隐身模式"基线采集（不登录）
  - API 降级为"快速预览"功能

Phase 3（6-12个月）: Browser-first 架构
  - 根据 Phase 2 的数据验证，决定全面切换时机
  - 建设账号池管理系统
  - 实现多画像（Persona）的 Browser 采集
  - API 保留为补充/降级通道
```

### QA 视角：数据质量才是真正的护城河

**关键质疑：所有竞品都在用 Browser 抓取，凭什么我们能做得比别人好？**

答案不在采集方式，而在**数据质量**。我们应该问自己：

1. **品牌提取准确率**——我们现在用60个品牌的正则匹配，太粗糙了。Profound 用的是实体识别 + 上下文语义理解。
2. **时间维度**——一次快照毫无意义。SEO 工具的价值在于**趋势追踪**："你的排名这周比上周上升了3位"。我们需要持续监测能力。
3. **可重复性**——我们的实测中，同一个问题两次问可能得到不同答案。这意味着单次采集的结果本身就有噪声。Profound 做了1.3亿次对话的聚合，我们做了10次。
4. **统计显著性**——从 QA 的角度，10个问题×2个平台 = 20个数据点，完全不够得出结论。我们需要至少 100+ 问题 × 4+ 平台 × 多次重复采集。

**QA 的建议：在辩论 API vs Browser 之前，先把采集规模和质量提上来。用什么方式采集是第二位的问题。**

### UX 视角：用户不关心你怎么采集，只关心结论可信

**核心观点：我们在讨论一个用户永远不会问的问题。**

品牌方用户不会问"你是用API还是浏览器采集的"。他们关心的是：

1. **"我在AI搜索中的表现怎么样？"** → 需要一个直观的分数/评级
2. **"比上个月好了还是差了？"** → 需要趋势图
3. **"我应该做什么来提升？"** → 需要可执行的建议
4. **"竞品表现如何？"** → 需要对比视图

**从 UX 角度看，SEO 行业最成功的产品转型是：**

| SEO 工具 | 早期 | 现在 |
|---------|------|------|
| 核心功能 | "你的关键词排第几" | "你的可见度健康度是85/100" |
| 数据展示 | 关键词排名表格 | 可见度趋势仪表盘 |
| 行动建议 | "提交更多外链" | "这5个内容点需要优化" |
| 报告风格 | 技术数据堆砌 | 管理层可读的洞察报告 |

**我们应该做的产品定位调整：**

不要说"你在豆包上排第3"（因为这个数字本身就不稳定），而是说：

> "在过去30天里，当消费者在AI平台上搜索'抗蓝光护肤品'相关问题时，你的品牌出现在回答中的概率是 **72%**，高于行业平均的 45%。你的主要竞品雅诗兰黛的出现概率是 **85%**。"

这种表述：
- 不依赖单次查询的精确排名
- 基于统计聚合，自然消化了 API/Browser 的差异和个性化的波动
- 给品牌方的感觉是专业、可信、可比较

## 五、综合结论：SEO 教会我们什么

### 5.1 三个核心教训

**教训一：数据采集方式跟着"真相"走，不跟着"方便"走**

SEO 工具从来没有因为"爬虫太难了"就放弃爬虫去找 API 捷径——因为消费者看到的就是 SERP 页面，不是API返回的JSON。同理，**消费者用浏览器和AI对话，不用API**，所以 Browser 采集方向是对的。

**教训二：个性化没有杀死行业，反而创造了更大的市场**

Google 个性化搜索出现后，SEO 市场从 $200 亿级增长到了 $750 亿级。原因很简单——越复杂的环境，品牌方越需要专业工具来理解和优化。**如果AI搜索个性化了，品牌方只会更需要我们。**

**教训三：产品定位比技术路线更重要**

SEMrush 的成功不是因为它爬虫爬得最好（Ahrefs 的爬虫更强），而是因为它把 SEO 数据包装成了**所有部门都能理解的可见度仪表盘**。技术基础设施是必要条件，但产品定位才决定天花板。

### 5.2 对"个性化威胁"的回应

| 担忧 | SEO 的经验告诉我们 |
|------|-------------------|
| "每个人看到的不一样，还怎么测？" | 用匿名/新账号测基线 + 统计聚合消化差异 |
| "排名不固定了，还有什么价值？" | 从"精确排名"转型为"可见度概率"，反而更有商业价值 |
| "API和Browser不一样，信谁？" | 信 Browser——这是消费者真实看到的。API 作为补充趋势指标 |
| "做Browser太贵太复杂" | SEO 巨头花了15年建基础设施。早期可以先做轻量版，逐步投入 |
| "个性化会让我们的数据失效" | 恰恰相反——个性化意味着品牌方更需要多维度监测工具 |

### 5.3 对"Browser 难题"的回应

| 难题 | 解决思路 | SEO 行业怎么做的 |
|------|---------|----------------|
| **慢** | 并行化 + 采样统计代替全量 | Ahrefs 不是实时排名，是定期快照 + 趋势推算 |
| **登录/账号** | 隐身模式测基线 + 测试账号池 | SEO 工具用匿名代理 + 地区模拟 |
| **DOM不稳定** | 抽象选择器层 + 自动化检测 + 快速修复 | SEO 工具有专门团队维护 SERP 解析器 |
| **成本** | 早期：云主机3-5台起步；规模化后：自建集群 | SEMrush 和 Ahrefs 都是逐步扩展基础设施 |
| **并发** | 分时段采集 + 优先级队列 | SEO 工具也不是实时的，周更/日更就足够 |

## 六、战略方向与行动计划

### 6.1 产品定位（立即调整）

**从**："帮品牌看在AI搜索中的排名"
**到**："帮品牌理解和优化在AI搜索中的可见度"

关键差异：
- "排名"暗示确定性（第1名、第3名），但AI回答不是这样工作的
- "可见度"暗示概率性（72%出现率），更准确也更有商业说服力
- 参照物：SEMrush 的 "Visibility Score"、Ahrefs 的 "Traffic Potential"

### 6.2 数据采集演进路线

```
┌─────────────────────────────────────────────────────────────┐
│  Phase 1: 混合校准期（现在 → Q2 2026）                        │
│  ─────────────────────────────────────────────                │
│  • API 做日常快速监测（分钟级）                                 │
│  • Browser 做周度校准采样（50-100题/平台/周）                   │
│  • 建立 API→Browser 偏差模型                                  │
│  • 投入：1-2 台云主机，$200-400/月                             │
│  • 对用户展示：校准后的可见度分数                                │
├─────────────────────────────────────────────────────────────┤
│  Phase 2: Browser 主力期（Q3-Q4 2026）                        │
│  ─────────────────────────────────────────────                │
│  • Browser 覆盖 4 平台，每平台日采样 200+ 次                    │
│  • 引入匿名模式基线 + 多画像采集                                │
│  • API 降级为"快速预览"和"趋势预警"                             │
│  • 投入：5-10 台云主机，$1,000-2,000/月                        │
│  • 新增指标："出现概率"、"趋势变化"                              │
├─────────────────────────────────────────────────────────────┤
│  Phase 3: 多维可见度平台（2027）                               │
│  ─────────────────────────────────────────────                │
│  • 支持 Persona-based 采集（模拟不同用户画像）                   │
│  • 统计显著性保障（每问题 N≥30 次重复采集）                      │
│  • 引入服务端日志分析（参考 Profound 的 Agent Analytics）         │
│  • 核心指标："分人群可见度"、"品牌健康度评分"                     │
│  • 如果 AI 个性化成熟，这个阶段的产品壁垒最高                    │
└─────────────────────────────────────────────────────────────┘
```

### 6.3 近期可执行动作（P0-P1）

| **P0** | 实现 Browser 隐身模式采集 | 去除登录/账号污染的"干净基线" | 3-5天 |
| **P1** | 设计"可见度分数"指标体系 | 替代"排名"的核心产品指标 | 1周 |
| **P1** | 部署 1 台云主机 + Browser 集群 | 验证远程 Browser 采集可行性 | 3-5天 |
| **P1** | 增强品牌提取能力 | 从正则匹配升级到 NER + 上下文理解 | 1-2周 |

### 6.4 商业价值总结

| 价值主张 | 基于 API | 基于 Browser | 基于混合架构 |

| 响应速度 | 快（分钟级） | 慢（小时级） | 中（分钟+日更） |
| 个性化适应性 | 无 | 可通过多画像扩展 | 可渐进演进 |

## 七、未解决的分歧

| 分歧点 | 正方立场 | 反方立场 |
|--------|---------|---------|
| **Browser 投入时机** | 应该立即开始，方向比速度重要 | 应该先验证 PMF 再投入基础设施 |

## 八、最终建议

> **方向明确，节奏务实。**

1. **方向**：Browser-first 是正确且必要的，这不是我们的判断，而是整个 AEO 行业（包括拿到红杉投资的 Profound）已经验证的路径。
2. **节奏**：但不必今天就 all-in Browser。SEMrush 花了15年建基础设施，我们作为初创公司，Phase 1 的"API主力 + Browser校准"是当下最务实的选择。
3. **产品**：不管用什么方式采集，产品表达从"排名"转向"可见度"是必须做的。这是 SEO 行业用15年验证的正确方向。
4. **个性化**：不恐慌，但做准备。我们的 A2 Persona Agent 是天然的多画像采集基础，这在个性化时代会变成核心竞争力。
