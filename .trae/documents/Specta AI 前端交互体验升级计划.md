## 分析总结

基于对 Manus 和 AnyGen 的参考，当前前端需要以下核心改进：

### 当前问题
1. **Pipeline 一口气运行** - 用户无法感知每一步的执行，也无法中途干预
2. **进度条交互** - 传统进度条设计，缺乏 AI Chat 的智能化交互感
3. **缺乏透明性** - 用户看不到 Agent 的思考过程和执行动作
4. **Canvas 交互弱** - 右侧 Canvas 展示不够动态和直观

### 参考产品亮点

**Manus 借鉴：**
- 主动回应用户输入，说明接下来要做什么（主回复内容）
- 思考与规划 Cell（层级弱于主回复）
- 执行动作 Cell（归属于规划，如"正在搜索"）
- 操作区域等待用户确认（浏览器授权等）
- 整体像"干活的真人"

**AnyGen 借鉴：**
- 两栏到三栏动态设计
- 左侧：项目列表
- 中间：Chat（Pipeline Cell 透明展示，可展开看流式输出）
- 右侧：Canvas（点击结果区域展开，显示文档/列表，带复制/分享/下载按钮）

## 整改计划

### Phase 1: 消息流重构 - Agent 透明化执行

**目标：** 让 Agent 的每一步都可见、可确认

1. **新增消息类型 - 执行步骤消息 (ExecutionStepMessage)**
   - 每个 Pipeline 步骤作为一个独立消息
   - 显示步骤名称、状态（进行中/已完成/等待确认）
   - 可展开查看详细执行日志（流式输出）

2. **重构 AgentMessage 组件**
   - 主回复内容：Agent 主动回应用户，说明要做什么
   - 思考 Cell：折叠状态，显示"正在思考..."
   - 规划 Cell：显示执行计划列表
   - 动作 Cell：显示当前执行的动作（如"正在搜索 DeepSeek..."）
   - 观察 Cell：显示执行结果摘要

3. **新增确认消息类型 (ConfirmationMessage)**
   - 当需要用户确认时，在消息流中插入确认卡片
   - 支持选项选择和文本输入
   - 用户确认后才继续下一步

### Phase 2: Pipeline 逐步执行改造

**目标：** 每步执行后暂停，等待用户确认

1. **后端改造**
   - 修改 Pipeline 执行逻辑，支持 step-by-step 模式
   - 每步完成后发送 WebSocket 消息等待确认
   - 新增 `step_completed` 和 `wait_for_confirmation` 事件

2. **前端改造**
   - 新增 `StepController` 组件
   - 显示"继续下一步" / "跳过此步" / "重新执行" 按钮
   - 用户可以查看当前步骤结果后再决定是否继续

### Phase 3: Canvas 动态交互增强

**目标：** 三栏动态布局，Canvas 可交互

1. **布局重构**
   - 左侧：项目/会话列表（可折叠）
   - 中间：Chat 区域
   - 右侧：Canvas 区域（动态展开）

2. **Canvas 触发机制**
   - 点击 Chat 中的输出卡片 → 右侧展开 Canvas
   - 支持多 Tab 切换
   - Canvas 头部添加操作按钮（复制、分享、下载）

3. **Canvas 内容类型**
   - 报告：Markdown 渲染 + 导出 PDF
   - 图表：交互式图表
   - 数据表：可排序、筛选的表格
   - 选择项：多选/单选界面

### Phase 4: 视觉与动效升级

**目标：** 打造"Wow"的智能感

1. **消息流式输出效果**
   - Agent 回复逐字显示（打字机效果）
   - 思考过程实时流式展示

2. **Cell 层级视觉区分**
   - 主回复：白色背景，突出显示
   - 思考/规划：灰色背景，折叠状态
   - 动作：带图标和动画效果
   - 观察：结果展示区域

3. **交互动效**
   - Cell 展开/收起动画
   - Canvas 滑入滑出动画
   - 确认按钮悬停效果
