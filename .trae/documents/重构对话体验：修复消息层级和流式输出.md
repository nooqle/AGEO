## 问题分析

通过调研Manus.im和对比当前实现，发现以下核心问题：

### 1. 消息层级混乱
**当前问题**：
- TPAOR序列（思考、规划、行动、观察）和回复消息混在一起
- 回复消息被当作TPAOR的一个阶段，可以折叠
- 用户看不到清晰的对话流程

**正确设计**（参考Manus/Kimi）：
- **用户消息**和**Agent回复消息**是同一层级，是对话的主体
- **思考、规划、执行、观察**是过程信息，应该可折叠
- 回复消息**永远不可折叠**，是主要展示内容

### 2. 流式输出体验差
**当前问题**：
- 用户输入后，只显示Progress组件转圈
- 没有实时的LLM流式回复
- 突然从Progress跳转到思考和回复两个cell

**正确设计**：
- 用户输入后，Agent应该**立即开始流式回复**
- 在回复的同时，后台执行TPAOR过程
- 过程信息（思考、执行等）以可折叠的形式展示在回复下方或旁边

### 3. 缺少实时反馈
**当前问题**：
- 用户看不到Agent正在思考什么
- 看不到执行进度
- 体验像"黑盒"

**正确设计**：
- 思考过程实时显示（可折叠）
- 执行步骤实时更新（可折叠）
- 主回复消息始终展开

## 修复方案

### Phase 1: 重构消息结构
**文件**: `frontend/src/components/chat/Message/AgentMessage.tsx`

**修改内容**：
1. 分离**主回复消息**和**TPAOR过程信息**
2. 主回复消息始终展开，显示在顶部
3. TPAOR过程信息作为可折叠区域，显示在回复下方
4. 移除回复消息作为TPAOR阶段的逻辑

### Phase 2: 修复流式输出
**文件**: `frontend/src/components/chat/hooks/useWebSocket.ts` 和相关组件

**修改内容**：
1. 确保LLM回复实时流式显示
2. 修复WebSocket消息处理逻辑
3. 确保用户输入后立即看到Agent开始回复

### Phase 3: 修复后端Agent逻辑
**文件**: `aeo-platform/backend/app/agents/general_react_v2.py`

**修改内容**：
1. 确保Agent立即开始生成回复（流式）
2. TPAOR过程信息作为独立事件发送
3. 修复回复消息和过程信息的分离

### Phase 4: 优化UI交互
**文件**: `frontend/src/components/chat/TPAORSequence.tsx`

**修改内容**：
1. 过程信息默认折叠，只显示标题
2. 用户可以点击展开查看详细过程
3. 添加"思考中..."、"执行中..."等状态提示

## 预期效果

修复后，对话体验应该是：

1. **用户输入** → 立即显示用户消息
2. **Agent开始回复** → 立即显示流式回复内容（不可折叠）
3. **过程信息** → 在回复下方显示可折叠的"思考过程"、"执行进度"等
4. **完整体验** → 类似Kimi Chat，主对话清晰，过程信息可展开查看

3. Phase 3: 修复后端Agent事件发送
